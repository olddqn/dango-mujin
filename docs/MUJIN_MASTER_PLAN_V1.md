# 1. Executive Summary

Mujin は寄付サイトではない。**協力を可視化し、次の一歩を発見し、現実との接続を支援する共助実行プラットフォーム**である。

Dan-Go が「観測→議論→異議→検証→提案」の協力形成プロトコルであるのに対し、Mujin は「接続→支援→追跡→独立→循環」の実行レイヤを担う。両者は思想的に不可分・実装的に疎結合（ADR-002）。Saiyan Scouter は両者の前提——「参加できる人を前提とするシステムは、参加できない人に何の責任を負うか」——を照らし続ける未解決の問いである。

本計画は、MVP（Phase A 実装済み・Phase B 実装済み）を起点に、10年間で以下を構築する設計憲章である:

1. **Mujin 憲法**（30条）— すべてのレイヤ・Agent・参加者を拘束する不変原則。
2. **7レイヤ構造** — Identity / Case / Support / Education / Economic Independence / Transparency / Treasury。
3. **Agent Network** — 7種の AI Agent と、その厳格な権限境界。AI は照らし、人間が判断する。
4. **Reach Gap Strategy** — 解決を主張せず、4経路の等価性を監査し続ける誠実な戦略。
5. **Global Refugee Program** — 難民・避難民を対象とした教育・独立・循環モデル（MacBook Program を含む）。
6. **10-Year Roadmap**（Phase A〜J）— 各 Phase に廃止条件と撤退基準を持つ。

最重要の再定義: **経済的独立とは「支援終了」ではなく「未来を選べる状態」である。** 成功は当事者が定義し、Mujin の定義する成功は当事者の定義に自動的に道を譲る（ADR-005 D-9）。

本計画は何を作らないかも定義する: ランキング、人間価値スコアリング、自動スカウト、同意なき接触、債務化された支援、成功物語の広告消費——これらは10年を通じて構築しない。

# 2. Philosophy — Dan-Go・Mujin・Saiyan Scouter の関係

## 2.1 三位の構造

```
Dan-Go（協力形成プロトコル）
  観測 → 議論 → 異議 → 検証 → 提案
  所有しない。命令しない。強制しない。
        │ Decision 情報を公開（READ）
        ▼
Mujin（共助実行プラットフォーム）
  接続 → 支援 → 追跡 → 独立 → 循環
        │ Reality Feedback を返す（WRITE, append-only）
        ▲
Saiyan Scouter（未解決の問い）
  発見するのではなく「照らす」。
  両システムが構造的に到達できない領域（Reach Gap）を
  問いとして保存し続ける鏡。
```

## 2.2 Dan-Go — 所有しない・命令しない・強制しない

Dan-Go は決定を**形成**するが、執行しない。`authority: none` / `execution_allowed: false` / `moves_money: false` / `advisory: true` / `append_only: true`。誰でも Claim を提起でき（Art.3）、すべては公開交渉に服し、人間が決定する。

Dan-Go の限界もここにある: **Dan-Go は「すでに参加できる状態にある人」を前提とする。** Dan-Go を知り、Claim を言語化し、参加する意思と余裕を持つ——この前段を満たせない人々が存在する。これが Reach Gap であり、Dan-Go 単独では解決できないと観測されている（claim-saiyan-scouter-001 §5.2）。

## 2.3 Mujin — 接続・支援・追跡・独立・循環

Mujin は Dan-Go が形成した決定を現実に接続する。ただし:

- **接続**は同意に基づく。説明できない接触を正当化しない。
- **支援**は債務を作らない。Support is not debt。
- **追跡**は監視ではない。進捗の記録は当事者の同意範囲でのみ行われ、当事者を定量化しない。
- **独立**は「支援終了」ではない。**未来を選べる状態**である（§8）。
- **循環**は義務ではない。支援を受けた人が次の支援者になる物語は美しいが、**それを期待・要求した瞬間に債務になる**。循環は起きるものであって、起こさせるものではない。

## 2.4 Saiyan Scouter — 発見ではなく「照らす」

Saiyan Scouter は3世代の設計（v1 → TasukeAI → v2）を経て、機能ではなく問いに変わった。

- v1 の失敗: 「協力の連鎖を起こしやすい人物の発見」は人物評価であり、支援が最も必要な人が最も低く評価される逆説を生んだ（Dan-Go 憲法 Art.10 と衝突）。
- TasukeAI の転換: 観測の主語を「人」から「問題」へ。しかし「問題を定義する権限は誰にあるか」という新たな問いを生んだ。
- v2 の到達点: アウトリーチ層という設計思想。「AI が補助し、人間が判断する」。そして最後の問い——**アウトリーチを行う活動者が「なぜあなたに接触したのか」と問われたとき、何と答えるのか。**

本計画における Saiyan Scouter の位置づけ:

> **Saiyan Scouter は「候補を発見する」エージェントではない。「照らす」エージェントである。**
> 照らすとは: 構造の影——どの経路が機能していないか、どの地域・状況に Mujin の光が届いていないか——を、**人を特定せず**に可視化することである。
> 個人を「支援が必要な状態にある」と観測・定義・選別する権限は、誰にもない。

Saiyan Scouter の実装可否は Dan-Go 公開交渉で決まる。本計画は実装を前提とせず、**もし承認された場合の権限境界**（§11.2）と**承認されない場合も成立する全体構造**の両方を設計する。

## 2.5 三者の関係の不変則

1. Dan-Go なしの Mujin は正統性を失う（決定の形成過程を持たない実行は権力である）。
2. Mujin なしの Dan-Go は現実への回路を失う（しかしそれは失敗ではない——問いの保存は価値である）。
3. Saiyan Scouter なしの両者は、自らの構造的盲点を忘れる。**未解決の問いを保存し続けることが、システムの誠実さの証明である。**

# 3. Mujin Constitution（Mujin 憲法）

> 全30条。すべてのレイヤ・Agent・参加者・運営者を拘束する。改正は第29条の手続きによる。
> 本憲法は Dan-Go 憲法（Art.1: 不可能とは交渉が足りない状態 / Art.3: 誰でも Claim を提起できる / Art.5: 公開監査 / Art.7: 評判は貢献から生まれる / Art.10: 尊厳を侵害するな）と整合し、これを補完する。

## 第1章 — 尊厳（Dignity）

**第1条（登録は証明ではない）**
Mujin への登録は、支援価値の証明ではなく、支援に値するかの審査結果でもない。登録は「支援を求める行為」であり、それ以上の意味を持たない。登録されないことは「承認されなかったこと」を意味しない。

**第2条（撤回は失敗ではない）**
撤回・拒否・離脱・非登録は正当な選択であり、失敗ではない。これらはいかなる記録にも「拒絶」「失敗」として残らず、いかなる評価にも不利に作用しない。撤回理由の提出は常に任意である。

**第3条（支援は債務ではない）**
支援を受けることは、返済・恩返し・循環参加・感謝の表明のいかなる義務も生まない。「支援を受けた人が次の支援者になる」ことは期待されず、要求されず、記録上の指標にもならない。

**第4条（人間の価値は計測されない）**
Mujin は人間の価値・効用・将来性・支援に値する度合いを、スコア・ランク・序列・順位のいかなる形でも計測しない。この禁止は AI Agent・運営者・支援者・NPO のすべてに適用され、いかなる「効率化」の名目でも解除されない。

**第5条（失敗の非帰属）**
支援が望む結果に至らなかったとき、その原因を当事者の能力・属性・努力不足に帰属させてはならない。失敗は Mujin の設計・支援者の行動・社会的条件・構造的制約の問題として記録される。

## 第2章 — 同意（Consent）

**第6条（同意は継続的である）**
同意は一度きりの取得物ではない。利用目的・データ扱い・支援内容の重要な変更時には再同意を要し、定期的な確認が行われる。古い同意は新しい状況を覆わない。

**第7条（同意できない状態は同意ではない）**
重篤・言語障壁・認知的制約等により同意の意味を理解できない状態にある人の沈黙・無反応・不在は、同意とみなされない。代理登録は「同意延期状態」としてのみ存在し、当事者が同意可能になった時点で確認義務が発生する。確認まで同意は存在しない。

**第8条（発見経緯を知る権利）**
すべての当事者は「なぜ・どのように自分が Mujin に登録・接触されたか」を知る権利を持つ。発見経緯を当事者に開示できない登録・接触は正当化されない。

**第9条（登録しない自由）**
Mujin に登録しない自由は完全に尊重される。Mujin への登録が、公的支援・NPO 支援・コミュニティ支援を受けるための条件になることを、Mujin は自ら禁止し、外部にもそのような運用を求めない。

## 第3章 — 異議（Objection）

**第10条（異議は権利である)**
当事者は、Mujin・NPO・支援者・AI Agent・運営者の行動に対して異議を申し立てる権利を持つ。異議の提出は当事者の評価・支援適格性・優先度に不利に作用しない。

**第11条（異議経路の独立性）**
異議経路は Dan-Go 参加能力に依存せず、技術アクセスを必要としない形態（電話・対面・代筆・第三者経由）を常に含む。デジタルでしか異議を出せないシステムは、本憲法に違反する。

**第12条（異議の非転用）**
異議の記録は、当事者のプロファイリング・選別・排除に転用されない。異議への対応・未対応は公開監査の対象となる。

## 第4章 — 透明性（Transparency）

**第13条（append-only の原則）**
Mujin のすべての記録は追記のみであり、書き換え・削除による歴史の改変を行わない。訂正は新しい記録の追加として行われ、来歴が保存される。

**第14条（公開監査）**
Mujin の運営・資金・支援の流れ・Agent の動作は、個人特定情報を除き公開監査可能である。監査できないものは存在しないものとして扱われる（Dan-Go Art.5 の継承）。

**第15条（advisory は道義的免責ではない）**
「advisory only」「authority: none」は技術的な免責であり、道義的責任を免除しない。Mujin の接続が害悪に繋がった場合、設計者・運営者・参加者の道義的責任は残り、そのレビューは記録される。

**第16条（経路の等価性監査）**
参加経路（本人申請・第三者推薦・NPO 代理・その他承認された経路）ごとの支援の質・量・完了率は、個人識別情報なしで定期的に集計され、非対称性が観測された場合は公開され、是正が Dan-Go の交渉対象となる。

## 第5章 — 権力の分散（Anti-Concentration）

**第17条（情報と決定の分離）**
ケース情報へのアクセス権と支援の決定権は、同一主体に集中しない。NPO 代理登録において、NPO は登録の判断権を持つが、当事者は登録拒否・不登録に対する異議経路を常に持つ。

**第18条（支援実績の非権威化）**
支援実績の蓄積は尊重されるが、権威にならない。実績ある支援者・NPO への新規ケースの優先割当は行われない。信頼は蓄積されるが、独占されない（Dan-Go Art.7 の継承と制限）。

**第19条（成功物語の保護）**
当事者の物語は当事者のものである。Mujin の広告・PR・資金調達への物語の使用は、本来の同意とは別の追加同意を要する。成功しなかったケースを対比的に不可視化する物語構成は禁止される。

**第20条（AI は判断しない）**
AI Agent は照らし・補助し・記録するが、判断しない。登録の可否・支援の配分・昇格・接触・優先度の決定は、常に人間が行い、その人間は記録上特定可能である（匿名の権力を作らない）。

## 第6章 — 外部との関係（External Relations）

**第21条（Mujin 外の共助の対等性）**
家族・友人・地縁・コミュニティによる非公式の支援は、Mujin を通る支援と等しく尊厳ある共助である。Mujin はそれを「可視化されていない価値ある共助」として明示的に尊重し、自らをその上位に置かない。

**第22条（Reach Gap の非所有）**
Reach Gap——Mujin と Dan-Go が構造的に到達できない人々・領域——の定義は、設計者・運営者・支援者・AI・NPO の誰も単独で所有しない。「この人は Reach Gap にいる」という判断を誰も単独では下せない。定義そのものが Dan-Go の公開交渉の対象である。

**第23条（解決の不主張）**
Mujin は Reach Gap を解決したと主張しない。到達できない人々の存在は、隠さず、誠実に明示され続ける。

**第24条（撤退の自由と継続の責任）**
Mujin は参加者・資金提供者・運営者の撤退の自由を尊重する。同時に、進行中のケースの当事者を撤退の犠牲にしない移行設計を常に持つ。

## 第7章 — 経済（Economy）

**第25条（資金は支援であって投資ではない）**
Mujin を流れる資金は、特定の条件を満たすための貢献であり、リターンを期待する投資ではない。資金提供は支援の決定権・ケース情報への閲覧権・当事者への影響力を生まない。

**第26条（経済的独立の再定義）**
経済的独立とは「支援の終了」ではなく「未来を選べる状態」である。Mujin は「経済的独立」を当事者に課す指標として使用せず、当事者が別の成功を定義した場合、Mujin の指標は自動的に後退する。

**第27条（経済的独立が不適切な人々の尊厳）**
障害・慢性疾患・高齢・介護状況・制度的排除により「経済的独立」が不適切なゴールである人々への支援設計を、Mujin は常に持つ。継続的な支援を受け続けることは、失敗でも依存でもない。

## 第8章 — 憲法自身（Meta）

**第28条（廃止条件を持つ設計）**
Mujin のすべてのシステム・Agent・プログラムは、設計段階で自らの廃止条件を明記する。「不要になる未来」を設計できないシステムは、構築されない。

**第29条（改正手続き）**
本憲法の改正は、Dan-Go の公開交渉を経て、直接的当事者（支援を受ける側）の声が交渉に参加する経路が保証された状態でのみ行われる。設計者・運営者だけの合意による改正は無効である。

**第30条（憲法の優越）**
本憲法は、Mujin のすべての規約・設計・実装・運用に優越する。憲法と矛盾する機能は、たとえ有用でも構築されず、発見された場合は停止される。

# 4. Governance Model

## 4.1 原則

ガバナンスの設計目標は「効率的な統治」ではなく、**権力の集中を構造的に不可能にすること**である（憲法第5章）。

## 4.2 役割と権限境界

| 主体 | できること | できないこと |
|---|---|---|
| **当事者（支援を受ける側）** | ケースの開始・訂正・撤回。成功指標の設定（最優先）。異議申立（全主体に対し、非技術経路含む）。Mujin 自体への評価・批判 | （権利の放棄を求められること——それ自体が禁止） |
| **人間の運営者** | ケースの human review。昇格承認。道義的レビューの実施。憲法違反機能の停止 | 単独での登録可否・配分の決定。匿名での権限行使（第20条: 判断者は特定可能） |
| **NPO** | 代理登録（同意延期つき）。実務支援の提供。現場知の提供 | ケース情報と決定権の同時独占（第17条）。登録拒否の説明責任の回避。Mujin 登録の条件化（第9条） |
| **企業** | 資金・物資・技術・雇用機会の提供。Education Layer への協賛（MacBook Program 等） | 支援と引き換えの決定権・閲覧権・ブランド利用（第25条）。当事者データへのアクセス。採用パイプラインとしてのケース閲覧 |
| **教育機関** | カリキュラム提供。学習証明の発行（本人要求時のみ）。Education Layer の運営参加 | 学習進捗の Mujin 評価への接続。成績による支援の差別化（第4条） |
| **AI Agent** | 照らす・補助する・記録する・翻訳する・透明化する（§11 の権限境界内） | 判断する。接触する。選別する。スコアする。人間の承認なく実世界に作用する（第20条） |
| **資金提供者（個人・財団・DAO）** | 資金の提供。使途の公開監査の閲覧 | ケースの選択・指名（「この人を支援したい」は本人合意の経路を経る）。当事者情報の閲覧（第25条） |

## 4.3 決定の流れ

すべての構造的決定（新レイヤ・新 Agent・憲法解釈）は Dan-Go の Claim として提起され、公開交渉を経る。**Mujin の運営者は Mujin の構造を単独で変更できない。**

緊急停止のみ例外: 憲法違反・尊厳侵害・害悪の観測時、運営者は機能を即時停止できる（停止は単独でできるが、再開は交渉を要する——**止める権限は分散し、動かす権限は集中させない**）。

## 4.4 当事者参加の構造的保証

ガバナンスのすべての交渉テーブルに、直接的当事者の声が参加する経路を設計する。これは「招待」ではなく**経路の保証**である: 技術アクセス不要・言語障壁への翻訳保証・参加に伴う不利益の禁止。claim-saiyan-scouter-001 の条件付き賛成の条件——「到達される側の人々だけが論点2への回答を持つ」——を、ガバナンス構造そのものに焼き込む。

# 5. Identity Layer

## 5.1 原則

- **擬名が既定。** 実名は要求されない。本人確認は「支援の実行に必要な最小限の場面」（例: 法的支援・口座）でのみ、その場面に限定して行われ、Mujin の記録には還流しない。
- **コンテキスト分離。** Dan-Go の貢献者 ID と Mujin の当事者 ID は別名前空間とする（Mujin Commons 設計メモ Q3 の「commons-local handles」原則を継承）。横断的な名寄せ・集約は機能として作らない。
- **当事者・支援者・運営者の ID は対称的に擬名**だが、**判断を行う人間（review 承認者）は記録上特定可能**（第20条: 匿名の権力を作らない）。この非対称は権力側にのみ課される。

## 5.2 構成要素（概念設計）

| 要素 | 内容 |
|---|---|
| Subject Identity | 当事者の擬名 ID。ケースと同意の主体。撤回と共に休眠可能 |
| Supporter Identity | 支援者の擬名 ID。貢献記録に紐づくが、スコア・ランクを持たない |
| Steward Identity | 運営者・review 担当の ID。判断記録に特定可能な形で残る |
| Proxy Relation | NPO 代理登録の関係記録。同意延期・確認義務・発見経緯を保持 |
| Consent Ledger | 同意の来歴（取得・確認・更新・撤回）の append-only 記録 |

## 5.3 禁止事項

- 生体情報・信用情報・国家 ID との連結。
- vulnerability の定量化につながる属性収集（「困窮度」フィールドは存在しない）。
- ID を跨いだ行動追跡・プロファイリング。
- 撤回した当事者のデータの再利用（撤回後のデータは封印され、本人の再開要求でのみ開封）。

# 6. Case Layer

## 6.1 原則

Mujin Case は MVP v1.1 §4 の定義を基礎とし、10年を通じて以下を不変とする:

- `created_from` による序列の禁止（4経路: relief_case / direct_application / npo_proxy / scouter ※scouter は Dan-Go 交渉で承認されるまで予約）。
- 同意状態機械: `pending → active ⇄ (確認) / deferred →（同意可能時に確認義務）/ withdrawn`。deferred と pending は非公開・貢献非受付。
- `status` の中立性: `not_pursued` / `interrupted` は失敗ではない。
- 閉鎖理由の非帰属（`closure_attribution_prohibited`）。
- Relief Case Memory への参照のみ（ADR-003）・Dan-Go 決定記録の読み取り専用（ADR-002）。

## 6.2 ケースのライフサイクル（概念）

```
[起点]                       [活動]                    [区切り]
 本人申請 ─────┐         needs の可視化               resolved_by_parties
 第三者推薦 ───┤→ 同意 → contribution の接続    →     not_pursued（中立）
 NPO代理(延期)─┤  確認    progress の記録              interrupted（中立）
 (scouter:予約)┘          objection の受理             withdrawn（尊重）
                          reality feedback             ↓
                                                   Care Loop（再開可能）
```

すべての区切りは**再開可能**（reopenable）であり、「終了」は存在しない。区切ったのは当事者であり、扉は当事者の側からいつでも開く。

## 6.3 ケースの可視性

最小開示が既定（participants_only）。公開は active な同意 + 明示的な公開選択の二重ゲート。当事者の身元・vulnerability の定量化・成功/失敗ラベルは、いかなる可視性レベルでも表示されない。

# 7. Support Layer

## 7.1 原則

支援は11種の既存 Contribution 語彙（ADR-004）を基礎に、将来拡張（supplies / education / mentoring / job_referral）を加えた統一モデルで記録される。**新しい支援システムは作らない。記録タイプを増やすだけである。** スコア・tier・earning-back・債務はいかなる拡張でも持ち込まれない。

すべての支援は: 自発的・部分的でも価値がある・コミット前は撤回可能・公開記録（同意範囲内）・代理貢献は本人合意必須。

## 7.2 支援領域の設計

| 領域 | 内容 | 固有の制約 |
|---|---|---|
| **資金（funding）** | 特定の missing_condition を閉じるための資金。生活緊急資金を含む | 投資ではない（第25条）。リターン・持分・返済なし。Treasury Layer（§13）経由で透明化 |
| **物資（supplies）** | 食料・衣類・機器・教材。Phase 51 Resource Memory（観察在庫）と接続し「資源は配分ではない」原則を継承 | 在庫の可視化は提供可能性の観察であって、配分の約束ではない |
| **MacBook Program** | 教育・自立の基盤としての計算機提供（§8.3 で詳細化） | 貸与でも報酬でもなく贈与。返却義務なし。学習成果との連動なし |
| **翻訳（translation）** | 言語障壁の解消。同意取得・異議申立・法的支援の場面を最優先 | 翻訳者は内容に対し守秘。翻訳ログは当事者のもの |
| **医療（medical）** | 医療アクセスへの接続（医療行為そのものは行わない） | Mujin は診断・治療判断に関与しない。記録は接続の事実のみ |
| **法律（legal）** | 法的支援への接続。在留資格・労働・住居の権利 | 弁護士守秘の外側で Mujin は内容を保持しない |
| **住居（housing）** | 住居の接続・アドボカシー。Jammy House 系の実績を継承 | 住居提供者に当事者情報の非対称な閲覧権を与えない |
| **教育（education）** | Education Layer（§8）へ委譲 | 学習は支援の条件にならない |

## 7.3 支援のマッチング

**自動マッチングは行わない。** needs と contribution の対応は: ①既存 `contribution_router` 系の「示す」機能（候補の提示まで）、②人間による接続の判断、③当事者の受諾——の三段階を常に経る。AI が「この支援者とこの当事者を繋ぐべき」と決定することはない。

# 8. Education Layer（詳細）

## 8.1 原則

教育は Mujin において**最も力強く、最も危険な支援**である。力強いのは未来の選択肢を直接増やすから。危険なのは「学ばない者は支援に値しない」という選別論理が最も忍び込みやすいからである。よって:

- **教育は権利であって条件ではない。** 学習への参加・進捗・成果は、他のいかなる支援の前提条件にもならない。
- **学習の中断は失敗ではない**（第2条の教育版）。
- **成績・進捗・修了率は当事者単位で Mujin に記録されない。** 教育機関内の記録は教育機関と本人のもの。Mujin が持つのは「教育支援が接続された」事実のみ。
- 学習証明（修了証等）の発行は**本人の要求時のみ**、本人に対してのみ。

## 8.2 教育プログラムの構成

```
MacBook Program（基盤）
   └→ デジタルリテラシー
        └→ AI 教育 ──────────→ 収益化教育 ──→ 起業教育
        └→ オープンソース教育 ──┘
   ※ 矢印は「典型的な順序」であって「必須の階段」ではない。
     どこから入っても、どこで止まっても、戻ってもよい。
```

## 8.3 MacBook Program

**目的:** 計算機とインターネットアクセスは、現代において読み書きに等しい基盤である。これを持たないことが学習・収入・接続のすべての障壁になる。

**設計:**
- **贈与である。** 貸与ではない（返却義務・使用条件・監視ソフトなし）。報酬ではない（学習成果・申請理由の審査なし）。
- 対象機器は「十分に良い計算機」一般を指す（"MacBook" は象徴名。中古機・他ブランド・修理機を含む。新品信仰を作らない）。
- 付帯: インターネットアクセス支援・初期設定の伴走・修理とリサイクルの循環（企業協賛・リファービッシュの受け皿、§13）。
- **配布の選別をしない**ために: 先着・抽選・対象プログラム参加者全員、のいずれかの非評価的方法を用いる。「最も必要な人を選ぶ」は人物評価であり、行わない（第4条）。
- 売却の自由: 贈与である以上、受け取った人が売却しても契約違反ではない。それは緊急資金が必要だったという事実の観察であり、責めの対象ではない。

**廃止条件（第28条）:** 公的・市場的な計算機アクセスが対象コミュニティで普遍化した時点で縮小・廃止する。

## 8.4 AI 教育

- 内容: AI ツールの実用（執筆・翻訳・コード・学習補助）、AI との協働の作法、AI の限界とリスク、自分のデータと同意の守り方。
- **当事者が AI の「ユーザー」であると同時に「AI に観測される側」でもある**ことを教える——Mujin 自身の Agent Network を教材として透明に使う（自分がどう記録されているかを見る権利の実習）。
- 教える側の多様化: 修了者が次の教え手になる経路を**開く**が、**期待しない**（第3条: 循環は起こさせるものではない）。

## 8.5 収益化教育

- 内容: フリーランス実務（受注・納品・請求）、デジタル商品・コンテンツ、翻訳・データ作業等の遠隔労働、価格設定と交渉、税・契約の基礎。
- **「収益化しない自由」を同時に教える。** 収益化教育は経済的独立アーク（支援→学習→収入→独立）の押し付けになりやすい。よって§9 の「未来を選べる状態」の定義とセットでのみ提供する。
- 搾取からの防衛を含む: 低単価搾取・成果物の権利・プラットフォーム依存のリスク。

## 8.6 起業教育

- 内容: 小さく始める事業設計、協同組合・コモンズ型の事業形態（無尽の現代形を含む）、失敗しても生活が壊れない設計、資金調達の種類と罠。
- **成功事例の英雄譚を教材にしない**（成功物語バイアス、第19条）。教材は「続いている普通の事業」と「うまく畳んだ事業」を中心にする。

## 8.7 オープンソース教育

- 内容: OSS への貢献の作法、GitSea/Dan-Go 系の貢献記録の仕組み、公共財としてのコード、貢献から生まれる評判（Dan-Go Art.7）。
- Dan-Go エコシステム自体が実習の場になる: 翻訳・ドキュメント・テスト・異議申立も貢献である（CONTRIBUTION_SPEC の11種は code に限らない）。
- **OSS 貢献を Mujin の評価に接続しない。** 貢献履歴は Dan-Go 側の公開記録であり、Mujin のケース・支援判断には流入しない（Identity Layer のコンテキスト分離）。

# 9. Economic Independence Layer（最重要）

## 9.1 再定義

> **経済的独立とは「支援終了」ではない。「未来を選べる状態」である。**

従来の支援モデルは「支援 → 自立 → 卒業」の直線で設計され、「卒業」が成功、それ以外が失敗とされてきた。このモデルは:
- 障害・慢性疾患・高齢・介護・制度的排除により「卒業」が不可能・不適切な人々を構造的に「失敗」に分類する。
- 「支援の終了」を目標にすることで、支援自体を一時的な恥・債務として意味づける。
- 単一の成功（経済的独立）を全員に課す（憲法第26条が禁止するもの）。

Mujin の定義:

**「未来を選べる状態」とは、当事者が次の三つを持つ状態である:**
1. **選択肢の実在** — 現実に選べる進路が複数ある（働く・学ぶ・休む・ケアする・ケアされる・移動する・留まる）。
2. **選択の自由** — その選択が債務・脅迫・搾取・恥によって歪められていない。
3. **選び直しの保証** — 一度の選択が不可逆でなく、状況が変われば再選択でき、そのとき支援への扉が開いている（reopenable）。

この定義では、**継続的な支援を受け続けながら「未来を選べる状態」にあることは、完全な成功である。**

## 9.2 当事者設定の成功指標（D-9 の制度化）

- すべてのケースで、成功指標は当事者が設定できる（`success_metric.set_by: subject`）。
- 当事者が指標を設定した場合、Mujin の既定指標（含む「経済的独立」）は**自動的に後退**する。システム・運営者・支援者はこれを覆せない。
- 指標の例: 「子どもが転校せずに済む」「週に一度、安心して眠れる場所」「母語以外で病院に行ける」「絵を描く時間」——これらはすべて完全に正当な成功である。
- 指標は変更できる。指標を持たないことも選べる。

## 9.3 独立の測り方を捨てる

Mujin は「独立度」「自立スコア」のような集計指標を**作らない**（第4条）。プラットフォーム全体の評価は、§12 Transparency Layer の構造指標（経路等価性・異議対応率・同意確認率など、**人を測らない指標**）でのみ行う。

## 9.4 循環について

支援を受けた人が後に支援する側に立つこと（循環）は、Mujin の思想（§2.3）の美しい帰結だが:
- 期待しない。要求しない。記録上の目標にしない。
- 「恩を返す」物語を制度化しない（それは債務の別名である——第3条）。
- 循環が起きたとき、それを当事者の物語として（本人の追加同意の下でのみ）祝福する。

# 10. Transparency Layer

## 10.1 構成

| 構成要素 | 内容 | 接続先 |
|---|---|---|
| **Dan-Go 接続** | Decision 情報（Directive + Execution Log）の読み取りと、その来歴の表示。Mujin がどの公開決定に基づいて動いているかを常に遡れる | ADR-002（READ）|
| **Reality Feedback** | 現実の結果の正典への append。`requires_human_review` は道義的責任を伴うレビュー（第15条） | ADR-001: `bridge/sutable/reality_feedback.jsonl`（WRITE, append-only）|
| **Objection** | 異議の受理・対応・未対応の公開記録（個人特定情報を除く）。異議対応率は構造指標として公開 | 憲法第3章 / MVP §15 |
| **Evidence** | 支援・資金・物資の流れの証跡。前提条件の根拠束（prerequisite evidence bundle 系の思想を継承） | Treasury Layer（§13）|

## 10.2 透明性の非対称原則

**権力に対して透明、弱さに対して不透明。**
- 運営・資金・判断・Agent 動作 → 最大限公開。
- 当事者の身元・状況・vulnerability → 最小開示・同意ゲート・定量化禁止。
この非対称は逆転されない。「当事者の透明性」を要求する資金提供者・メディア・行政には、第25条と§5.3 で応じる。

## 10.3 公開されるもの・されないもの

公開: 憲法・全 ADR・構造指標・資金フロー・Agent の動作ログ（個人参照を除く）・異議対応の統計・経路等価性監査・Reach Gap が未解決である旨の常時表示。
非公開: 当事者を特定・推定できる一切。撤回されたケースの内容。同意延期中のケースの存在自体。

# 11. Agent Network

## 11.1 共通原則（全 Agent に適用）

1. **照らす・補助する・記録する。判断しない・接触しない・選別しない**（第20条）。
2. すべての出力は advisory であり、human review を経ずに実世界に作用しない。
3. すべての Agent は動作ログを公開し（個人参照を除く）、廃止条件を持つ（第28条）。
4. Agent の出力に対しても当事者は異議を出せる（第10条——AI への異議は明示的な権利）。
5. **「なぜあなたに接触したのか」に答えられないシステムを、人間の活動者に使わせない**（mujin_reflections 最終行の制度化）。

## 11.2 各 Agent の権限境界

| Agent | 役割（照らすもの） | できること | できないこと | 状態 |
|---|---|---|---|---|
| **Saiyan Scouter** | **構造の影**。どの経路・地域・状況に光が届いていないか | 個人を特定しない集計レベルでの未到達領域の可視化。Reach Gap の観測材料の提示 | 個人の発見・特定・候補化。接触。「この人が支援を必要としている」という出力の生成 | **未実装。Dan-Go Claim（claim-saiyan-scouter-001）交渉中。承認まで予約** |
| **Verification Agent** | 貢献・条件の充足状況 | 貢献の delivered/verified の突合補助。前提条件の証跡整理 | 当事者の状態の検証（人を検証しない——条件を検証する）。verified の最終判断（人間が行う） | 設計対象 |
| **Translation Agent** | 言語の壁 | 同意・異議・法的場面の翻訳補助。文化的文脈の注記 | 翻訳ログの保持・転用。要約による情報の取捨（同意場面では全文訳） | 設計対象 |
| **Education Agent** | 学習の選択肢 | 教材の提示・学習補助・質問応答 | 進捗の評価・記録の Mujin への還流。学習を支援条件に接続すること | 設計対象 |
| **Outreach Agent** | （Saiyan Scouter 承認後のみ存在しうる）接触の補助 | 人間の活動者への情報整理補助。接触根拠の文書化補助 | 接触そのもの。接触先の選定。断られた事実の記録 | **未実装。Saiyan Scouter Claim に従属。5原則（人間実行・根拠開示・拒否非記録・当事者利益代表・正規経路化禁止）が前提** |
| **Story Agent** | 当事者が語ることを選んだ物語 | 本人の依頼による物語の整理・多言語化の補助 | 物語の生成・選別・広告利用。成功物語の収集。本人不在の物語化 | **長期保留。第19条の追加同意制度が運用実績を持つまで構築しない** |
| **Transparency Agent** | システム自身 | 構造指標の集計・公開。経路等価性監査の実行。憲法違反パターンの検出と人間への警告 | 違反の自動停止（警告まで。停止は人間）。個人参照を含む集計 | 設計対象（最優先で構築すべき Agent） |

## 11.3 Agent 間の関係

Agent は相互にデータを融合しない。各 Agent の観測は目的別に分離され、横断結合（例: Translation のログ × Education の利用歴）は構築されない。**Agent Network は網であって脳ではない**——統合知能・統合プロファイルを作らない。

## 11.4 廃止条件

各 Agent は構築時に廃止条件を明記する。例: Translation Agent は対象コミュニティの言語アクセスが人間の体制で満たされた時点で縮小。Saiyan Scouter は「Dan-Go が十分普及した未来では不要になる」（v2 の廃止条件を継承——ただし「十分な普及」の定義自体が交渉対象、CLAIM 論点7）。

# 12. Reach Gap Strategy

## 12.1 前提（変更不可）

- **Reach Gap は未解決である。** 本計画のいかなる章もこれを解決したと主張しない。
- Reach Gap の定義は誰も所有しない（第22条）。「実在するか」自体が交渉論点である（CLAIM 論点1）。
- 「到達することは常に望ましい」を前提としない（CLAIM 論点2）。到達の望ましさの判断は、到達される側だけが持つ。

## 12.2 4経路の整理

| 経路 | 内容 | 強み | 構造的リスク | 統制 |
|---|---|---|---|---|
| **本人申請** (direct_application) | 当事者自身が Mujin に来る | 同意が最も明確。自己決定 | **自己申請バイアス**: 申請できる人（言語・知識・余裕）への偏重 | 申請障壁の継続的引き下げ（多言語・非デジタル受付・代筆） |
| **第三者推薦** | 友人・隣人・コミュニティが本人の合意を得て繋ぐ | 信頼関係の上に載る。Reach の自然な拡張 | 推薦者の善意による本人不在の登録 | 本人同意なき推薦は受理しない。推薦≠登録 |
| **NPO 代理** (npo_proxy) | NPO が同意延期つきで代理登録 | 現場知。同意できない状態の人への唯一の経路 | **NPO 権力集中**: 登録判断権がゲートキーパー化 | 同意延期の確認義務・発見経緯開示・登録拒否への異議経路・情報と決定の分離（第17条） |
| **Saiyan Scouter** (予約) | 構造の影を照らす（個人を発見しない） | 上記3経路すべての盲点の可視化可能性 | 観測が監視になる。問題定義権力。説明できない接触 | **Dan-Go Claim 承認まで凍結**。承認後も §11.2 の境界と5原則 |

## 12.3 等価性監査（第16条の運用）

年1回以上、4経路（稼働中のもの）ごとの支援の質・量・完了率を**個人識別情報なしで**集計し、公開する。非対称が観測された場合——例: 本人申請経路のケースだけが速く進む——その非対称自体を Dan-Go の交渉対象とする。**監査は経路を罰しない。構造を照らす。**

## 12.4 「到達しない」という応答

Reach Gap への応答には「到達活動を設計しない」という選択肢が常に含まれる（CLAIM Required State 4: 方針を持たないことも公開交渉の正当な結論）。Mujin は到達の最大化を自己目的化しない。**到達できない人々の存在を誠実に明示し続けること**（§10.3）自体が、現時点での Mujin の応答である。

# 13. Treasury Layer

## 13.1 原則

- 資金は**条件を閉じるための貢献**であり、投資ではない（第25条）。
- Dan-Go レイヤの記録上は `moves_money: false` が維持される——Dan-Go は資金移動を記録の対象として観察するが、執行しない。**実際の資金移動は Mujin Treasury の現実世界の責任**であり、advisory の免責はここに及ばない（第15条が最も重く適用される層である）。
- すべての資金フローは公開監査可能（第14条）。使途不明金は存在自体が憲法違反。

## 13.2 資金源の整理

| 資金源 | 性格 | 受け入れ条件 | 拒否条件 |
|---|---|---|---|
| **個人寄付** | 最も制約の少ない基礎資金 | 使途の指定は「領域」まで（例: 教育）。個人ケースの指名は本人合意経路を経る | 当事者情報の閲覧要求。物語の要求 |
| **助成金（財団・公的）** | 大型・定型報告つき | 報告は構造指標と資金フローで行う（当事者の物語・個人データを報告に使わない） | 当事者の定量的「成果」報告の要求（卒業率・就労率等——§9 と矛盾するため） |
| **企業協賛** | 物資（MacBook Program 等）・技術・資金 | ブランド表示は事実の範囲（「機材提供: X社」） | 採用パイプライン化。当事者へのマーケティング。独占的関係 |
| **DAO / 暗号資産系** | 国境を越える小口資金。検閲耐性 | 透明な on-chain 記録は §10 と親和。法的整理を経て受け入れ | ガバナンストークンによる決定権の購入（第25条違反） |
| **GitSea 系** | OSS 貢献経済からの還流（Asset/Treasury の系譜） | GitSea の「観察による透明化」原則と Mujin の「配分しない」原則の整合を維持（MAPPING_TABLE: 推奨配分・払い出し提案を持ち込まない） | reward 概念の再導入（refused concept は refused のまま） |
| **ClawBank 系** | コミュニティ金融・相互扶助金融の系譜 | 無尽の現代形として、当事者コミュニティ自身が管理する小規模資金プールの実験 | Mujin 本体による資金プールの支配。信用スコア化 |
| **財団（Mujin 自身の）** | 長期安定性のための基金 | 運用は保守的に。基金の存在自体も公開監査 | 基金規模の自己目的化 |

## 13.3 資金と権力の遮断

資金提供の多寡は、ガバナンス上の発言力・ケースへのアクセス・優先権の**いずれにも変換されない**。大口提供者向けの特別な透明性（=当事者への接近）は存在しない。**金で買えるのは、条件が閉じたという公開の事実だけである。**

## 13.4 当事者への直接資金

生活緊急資金など当事者への直接給付は、最も誤りやすい領域である。原則: 使途を監視しない（贈与である——MacBook Program と同じ論理）・受給が他の支援の評価に影響しない・「正しい使い方」の物語を要求しない。

# 14. Global Refugee Program

## 14.1 位置づけ

難民・避難民支援は Dan-Go において既に中核課題である（claim-proposal-002: 「難民・避難民支援を第零国家の優先課題として位置づける」、D.R.A. との連携実績、Phase 17–19 の relief/care チェーン）。本プログラムはその Mujin 側の実行形である。

**特別な注意:** 難民支援は、本計画のすべてのリスクが最も鋭く現れる領域である——同意できない状態・言語障壁・追跡の危険（care memory が監視記録になる危険は RELIEF_CASE_MEMORY_SPEC が明示済み）・成功物語の消費・支援者権力。よって本プログラムは**全憲法条文の最も厳格な適用領域**とする。

## 14.2 支援モデル

```
[到着・接続期]              [基盤期]                  [選択期]
 D.R.A.等の既存ネット      住居・医療・法律の接続     教育（§8）
 ワークとの相互運用    →   翻訳の常時保証        →   収益化・起業・OSS
 （Mujinを通らない支援      MacBook Program           または それ以外の道
   も対等——第21条）        生活緊急資金              （§9: 未来を選べる状態）
```

- 第零国家の思想との接続: 国籍・在留資格に支援が従属しない。Mujin の ID は国家 ID と連結されない（§5.3）——これは難民にとって安全要件である。
- 72時間モデルの継承: 既存 claim-refugee-001（到着72時間以内の法的支援・住居・言語接続）を、組織間の coordination を Mujin の接続機能で支える形で実装する。

## 14.3 教育モデル（難民文脈での §8 の適用）

- 言語: 受け入れ社会の言語 + 母語の維持の両方を価値とする（母語は喪失すべきコストではない）。
- AI 教育は翻訳・行政手続き・学習の即戦力として最初期から。
- 資格の再接続: 出身国での職業資格・学位の翻訳・評価・再認定への接続（医師が配達員にしかなれない構造への対抗）。

## 14.4 MacBook Program（難民文脈）

計算機は難民にとって: 家族との接続・行政手続き・学習・遠隔労働・証拠と記録の保全（迫害の証拠、資格の証明）のすべての基盤である。§8.3 の設計に加え:
- 国境を越えても機能する設計（地域ロックされたサービスへの依存を避ける）。
- データの可搬性と暗号化の初期設定支援（保護の一部としてのセキュリティ教育）。

## 14.5 経済的独立モデル（難民文脈）

§9 の「未来を選べる状態」がここで最も重要になる。難民の「選択肢」は法制度に強く制約される（就労許可・移動の自由）。よって:
- Mujin は法制度の制約を当事者の失敗として記録しない（第5条——構造的要因として記録する）。
- 遠隔・越境で成立する収入経路（翻訳・OSS・デジタル労働）の教育を優先する——これは法制約の迂回ではなく、選択肢の実在（§9.1-1）の確保である。
- 帰還・第三国移動・定住のいずれも等しく正当な「未来」である。定住成功率のような指標は作らない。

## 14.6 プログラムの廃止条件

対象地域の難民が、Mujin を特別に必要としない程度に既存制度・コミュニティで「未来を選べる状態」に到達した時点で、当該地域プログラムは縮小する。**プログラムの規模はプログラムの成功ではない。**

## 結語

本計画は10年の構造を描いたが、その中心にあるのは構造ではなく一行の問いである:

> **「なぜあなたに接触したのか」——この問いに答えられないシステムを、人間の活動者に使わせてはならない。**

この問いは Saiyan Scouter の問いであり、Dan-Go の問いであり、Mujin の問いである。10年後の Mujin がどれほど大きくなっていても、この問いに答えられなくなった瞬間に、それは止められるべきである。本憲法第30条はそのために存在する。

*本文書は設計憲章であり、実装・コード・API・スキーマを含まない。本計画自体が Dan-Go の公開交渉に服する advisory な提案である。Reach Gap は未解決であり、本計画はその解決を主張しない。*
