## 1. 4ケースの観察

### Case A — JAR 単独
- JAR は実在・稼働し、公開要請を持ち、寄付/人手を受け取り、難民を支援する。**Mujin が無くても完全に機能する。**

### Case B — 寄付者単独
- 難民を助けたい寄付者は、単独で検索し JAR（や他団体）を見つけ、**JAR の公開ページから直接寄付できる**。動機ある寄付者は Mujin 無しで JAR に到達できる。

### Case C — JAR + 寄付者（Mujin なし）
- 寄付者が JAR の公開要請を見つけ、寄付/ボランティアする。**これは既に完結したループ**: 難民（JAR 経由）← JAR ← 寄付者。
- **JAR の資金モデル（民間寄付約7割）は、この Case C が規模で機能している実態そのもの。** Mujin 無しで完全に成立。

### Case D — JAR + 寄付者 + Mujin
- **Mujin は何を足すか、正直に検証:**

| 候補となる価値 | この場合の実際 |
|---|---|
| 接続 | 寄付者と JAR は直接接続できる（JAR は公開で findable）。**Mujin は接続を足さない。** |
| 発見 | 既に難民支援を望む寄付者は JAR を検索で見つけられる。JAR は高可視。**発見価値ほぼなし。** |
| 調整 | 単一の寄付者→JAR に調整は不要。調整価値は多数の need×多数の貢献者の matching でのみ立つ——ここにはない。 |
| 可視化/legibility | Mujin は協力を記録・透明化できる。だがそれは **Mujin/観察者への価値**で、JAR・寄付者・難民への救済価値ではない。 |
| Reality Feedback | JAR は既に寄付者に報告する。難民の結果は JAR の領分。**Mujin の feedback は観察であって新能力ではない。** |

→ **この場面で Mujin が足すのは記録・観察のオーバーヘッドであって、救済能力ではない。**

## 3. 中心観察 — 「なぜ Mujin なのか」に答えられるか

**この場面（JAR + 寄付者）では、答えられない。**

- **限界救済能力 = 0。** Case C で人は助かる（Mujin 無しで）。よって Mujin の**追加的な**救済貢献はゼロ。評価フレーム（「Mujin が無ければ助からなかった人が助かるか」）に照らし、ここでは**助かる人は Mujin に依存していない**。
- これは分析の失敗ではなく、**分析が機能している**証拠。「JAR に接触するな、Mujin は JAR/寄付者に提供する独自価値を持たないから」を告げている。

## 4. では Mujin の価値はどこにありうるか（未証明）

Mujin の独自価値は、**Case C が成立しない場面**にのみ立ちうる:

| Mujin が価値を持ちうる場面（未証明・n=0） | なぜ C では足りないか |
|---|---|
| need-bearer が既存 Gateway に未接続（gap-1） | だが Mujin もそこへ到達できない（Reach Gap） |
| 多数の need × 多数の貢献者の matching | 単一寄付者→JAR には不要 |
| 既存 Gateway/チャネルが無い need | JAR は既存・高可視 |
| 貢献者がどこで動けばいいか分からない | JAR を望む寄付者は JAR を見つけられる |
| 複数 Gateway/Solution を跨ぐ調整 | ここには1組織しかない |

- これらは D-2〜D-7（Solution/Cooperation Commons）が想定した仮説だが、**すべて未証明**。
- **JAR + 寄付者は、価値検証の場として誤っている**——既に C が閉じるから。**正しい検証対象は、C が閉じない場面**（既存 Gateway の無い need / どこで動くか分からない貢献者 / 多対多の調整）。

## 5. 暫定結論と最も安全な次の一歩

- **「なぜ Mujin なのか」は JAR 接触については答えられない。** Mujin の限界救済能力がこの場面でゼロだから。X-6.5 の「接触しない」結論を**価値の側からも**裏付ける。
- **JAR への接触は、Mujin の価値が無い場所に Mujin を挿入すること**になる。正当化されない。
- **最も安全かつ生産的な次の一歩:** JAR ではなく、**Case C が閉じない場面を探す/観察すること**。
  - 既存 Gateway の無い need が voice として現れるか。
  - 貢献者が「どこで動けばいいか分からない」状況があるか。
  - これらこそ Mujin の存在理由（仮説）を検証できる場面。
- **この発見はプロジェクトの根本的緊張の再確認**（最初の監査群から一貫）: Mujin は、既に閉じる場面では不要な中間者になる危険を持ち、閉じない場面（Reach Gap）には到達できない。**その狭間に Mujin の真の価値があるかは、まだ証明されていない。**

## 6. 正直な留保（ニヒリズムに陥らないために）

- 「この場面で価値ゼロ」は「Mujin に価値が無い」ではない。**Mujin の価値命題は原理的には実在しうる（C が閉じない場面で）。ただし実証はゼロ。**
- 評価フレームの目的（救えるのに救われない人を減らす）に照らせば、**Mujin が証明すべきは「C では助からなかった人が Mujin で助かった」事例を一件作ること**。JAR + 寄付者ではその事例は作れない（C で助かる）。
- ゆえに本レビューは「Mujin をやめろ」ではなく「**Mujin の価値を JAR で測るな・C が閉じない場所で測れ**」と告げている。
