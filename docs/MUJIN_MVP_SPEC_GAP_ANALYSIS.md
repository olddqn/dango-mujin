## 0. 来歴に関する重大な発見（Provenance Gap）

**REFL は「現行 Mujin 設計」として複数の成果物を前提にしているが、それらはリポジトリにも git 履歴にも存在しない。**

| REFL が前提とする成果物 | リポジトリ内存在 |
|---|---|
| Mujin Safety Constitution（8項目、項目8=支援者透明性レポート） | **無し** |
| `ConsentRecord` scope `{public_summary, support_connection, scouter_export, story_publication, progress_tracking}` + `revocable: true` | **無し** |
| `independence_roadmap` / Milestone | **無し** |
| 支援者 `trust_score`（Mujin 文脈） | **無し**（`runtime/trust_score.py` は Dan-Go 貢献用で別物） |
| 登録 Level 0–2（代理登録） | **無し** |
| `created_from` 4値 | SPEC §4 のみ（REFL が初出概念、Dan-Go 側に実装無し） |

**含意:** REFL は本リポジトリの外（別の設計対話）で形成された Mujin 設計を前提にしている。SPEC はそれを参照せず**独自の最小同意モデルを新設**した。この結果、SPEC の同意モデルと REFL の `ConsentRecord` が**別スキーマで乖離**している（→ 矛盾 X-1）。これは Open Question として残すべき来歴問題である。

## 9. 結論

SPEC は不変条件8項目とリスク R1–R5 を捕捉しており**骨格は健全**だが、ソースが要求する**運用メカニズム**（等価性監査・帰属禁止・独立異議経路・代理登録の同意延期）と、**思想の根幹**（advisory ≠ 道義的免責、到達の望ましさは到達される側が持つ、Reach Gap 定義の非所有）を欠く。とりわけ **MI-1/X-3（当事者の独立異議経路）と X-2/MR-5（道義的責任）** は、ソースが「これがなければシステムを人間に使わせてはならない」と述べた一線に直接関わる。

**Saiyan Scouter 問題（Reach Gap）は未解決であり、本ギャップ分析もその解決を主張しない。** 上記ギャップの解消は、CLAIM が要求するとおり**設計者だけの議論ではなく、到達される側の声を含む Dan-Go 公開交渉**を経るべきである。
