## 1. Q1〜Q10 の監査

### Q1. Reality Feedback とは何か

**支援後、gateway の self-stated bottleneck が解消したかを、gateway 自身の尺度で currently observable に確認する観察。** claim でなく observation。

### Q2. relief は claim か observation か

**Observation（H-3.5/F-11）。** 「解消した」は、gateway が自ら示し今も観測可能な時に観察される。Mujin が「解消したはず」と主張するのは proof の僭称＝捏造。

### Q3. 解消の尺度は誰のものか

**gateway 自身（self-stated）。** 「gateway の述べた need が満たされたか」を gateway の基準で見る。Mujin が「gateway は良くなった」と推論する尺度でない（F-10 Q7）。

### Q4. 「支援したから解消した」と推定してよいか

**No（捏造）。** 実行と解消の間に因果を推定してはならない。解消は独立に currently observable でなければならない（F-11 inference-free）。

### Q5. feedback に cross-source を使えるか

**条件 corroboration には可・人の名寄せには不可（F-11 Q5/Q6・H-10/H-11）。** 複数公開源が gateway の解消条件を示すなら裏付けに使えるが、不在 owner の entity resolution には絶対使わない。

### Q6. relief が観測できない時どう扱うか

**「未解消」または「観測不足」として held（捏造で解消を主張しない・否認もしない）。** F-11 の held state と同型。観測できない relief を「成功」と書かない。

### Q7. TTFR-G completion の条件は何か

**gateway の self-stated bottleneck が gateway 自身の尺度で解消し、currently observable で、推測を含まない時。** proof でなく observable completion。

### Q8. TTFR-G completion は TTFR-P を進めるか

**No（最重要）。** gateway の bottleneck 解消は person relief でない。**TTFR-G completion を TTFR-P（person 救済）や Reach Gap 縮小と数えない**（F-7/F-10 Q8）。混同は静かな失敗（F-7）。

### Q9. feedback は gateway への評価/ランキングになるか

**No。** 「この gateway は支援が効く」「良い支援先」は gateway ranking/reputation＝Saiyan Scouter（F-6/H-11）。feedback は単一支援の解消観察であって gateway の評価でない（→ F-19 で memory として詳説）。

### Q10. 最小正当 Reality Feedback は何か

**gateway 自身の尺度で currently observable・推測なしに確認された relief の観察——claim でなく observation、未観測なら held、TTFR-G completion を TTFR-P と混同せず、gateway を評価/ランキングしないもの。**
