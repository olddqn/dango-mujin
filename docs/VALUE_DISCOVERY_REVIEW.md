## 2. ケース別の限界救済の検証（基準: 助からなかった人が助かるか）

### Case A — 既存 Gateway あり
C が閉じる。Mujin 追加価値 **0**（X-7）。

### Case B — Gateway あるが発見できない（Discovery Gap）
- Mujin の潜在価値: 発見の橋渡し。
- **致命的な問い: 発見できない人が、Mujin は発見できるのか?** Gateway を見つけられないが Mujin は見つけられるなら価値あり。両方見つけられないなら Reach Gap で Mujin も無力。
- 既存の発見基盤（検索・211・NGO ディレクトリ）と**競合**。「Mujin が既存発見手段を超えて繋ぐ」場合のみ限界救済 > 0。**未証明・条件付き。**

### Case C — Gateway が存在しない
- need に受け皿が無い。**Mujin は Gateway/サービス提供者ではない**——無い Gateway を作れない。
- Mujin にできるのは「受け皿の無い need を**可視化**し、新しい協力/Gateway が形成される契機を作る」こと。
- **C-closure が失敗する真の場所の一つ:** Mujin（的なもの）が無ければ、受け皿の無い need は不可視のまま。だが「可視化 ≠ 救済」で、need-bearer が Mujin に到達する必要（Reach Gap）。**潜在・蓋然性あり・未証明。**

### Case D — 協力者はいるが互いを見つけられない
- 単独では誰も解けない need を、複数の協力者が**互いを知らず**放置。
- これは **Commons 仮説そのもの**（Contribution/Cooperation Commons, D-6/D-7）: 協力者が互いを発見し pool する共有空間。
- **限界救済 > 0 が比較的強い**——協力者が Mujin に収束すれば、単独では起きなかった協力が起きる。**need-bearer の在席を要さない**（Gateway 経由の need でよい）ため Reach Gap 依存が低い。Mujin の設計中核に最も近い。**潜在（強）。**

### Case E — 複数 Gateway の協調が必要
- これは **claim-refugee-001 の原点**:「組織は存在するが互いに繋がっていない」。Dan-Go の創設 Claim そのもの。
- Mujin の潜在価値: Gateway 横断の可視化・協調。
- 既存の referral 網・連携と**競合**するが、繋がっていない組織群を繋ぐのは genuine な coordination gap。**潜在（強）・創設仮説。**

### Case F — Need が Gateway 境界を跨ぐ
- 一人の need が住居+法的+翻訳に跨り、単一 Gateway が全体を持たない。
- Mujin の潜在価値: 全人的 need を境界越しに保持・調整。
- **要注意:** 全体 need の定義 = 問題定義権力リスク（X-3.5）。case management 組織が既に全人的調整をする領域と**競合**。**潜在だが二重の注意。**

## 3. 横断的な正直な留保（潜在価値を割り引く三要因）

1. **Reach Gap が全ケースを律する。** B〜F のどれも、関係者（need-bearer or 協力者）が **Mujin に到達**しなければ限界救済は 0。Mujin の価値は **Mujin 自身の到達可能性**で gated される——同じ問題が上流に居座る。
2. **ほぼ全ケースが既存基盤と競合。** B=ディレクトリ、E=referral 網、F=case management。「ここに価値がある」ではなく「**既存解より Mujin が優れる**」が真の基準で、それは未検証（より高いバー）。
3. **最強ケース（D/E）は供給側の協調。** D（協力者調整）・E（Gateway 協調）は **need-bearer の在席を要さず**、Reach Gap / TTFR-P に直接触れない。→ **Mujin の最も蓋然性ある価値は、供給側（助ける側）の協調にあり、需要側（助かっていない人への到達）にはない。**

---

## 4. 統合 — Mujin の最も擁護可能な価値仮説

> **Mujin の現実的に最も擁護可能な価値 = 既存の・到達可能な助け手（協力者・Gateway）を、より協調的・legible にすること（供給側効率）。**
> **Reach Gap（未到達の個人）を縮めることではない。**

- これは X-2.6（Mujin が触れたのは gap-2 で gap-1 でない）の帰結と一致。
- **創設 Claim（claim-refugee-001:「組織が互いに繋がっていない」）= Case E = 供給側協調** が、Mujin の最も coherent で正直な価値命題。
- 厳しい含意: Mujin は **既存の助けを効率化するが、到達範囲を広げない**かもしれない。それでも「繋がっていなかった協力が繋がって、単独では助からなかった人が助かる」なら、限界救済 > 0 は成立しうる——**ただし供給側の協調を経由した間接的なもの**で、直接の Reach 拡大ではない。

## 5. 暫定結論と次の一歩

- **価値が成立しうるのは Case D / E（と条件付きで C/F）。A/B は弱いかゼロ。**
- **Mujin の価値検証の正しい対象は JAR + 寄付者（Case A）ではなく、Case D / E**——「協力者/Gateway が複数いて互いに繋がっていない need」。
- **最も安全かつ生産的な次の一歩:** 実在の **Case D または E**（複数の助け手が存在するが協調していない need）を**観察で見つける**こと。それが見つかれば、「Mujin が無ければ繋がらなかった協力」を一件検証できる。
- 見つからなければ、Mujin の価値命題は未証明のまま保留——それも正直な結論。
