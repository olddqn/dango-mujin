## 0. 最重要の前置き — 二種類の「Need Candidate」を分ける

voice-006 は Gateway Voice（仲介者の声）である。ここから人間が考える Need Candidate は、**性質の異なる二種類**に分かれる。混同が Saiyan Scouter 問題の入口になる。

| 種類 | 何の Need か | 出所 | 危険度 |
|---|---|---|---|
| **(I) 仲介者の資源 Need** | JAR が活動を続けるための資源（資金・人手） | JAR の**公開要請に明示** | 低（本人不在でも JAR 自身の声） |
| **(II) 当事者個人の Need** | 難民個人が何を必要としているか（翻訳・法的・就労…） | JAR の**活動分野からの推測** | **高（不在の個人の Need を声から推測する＝問題定義権力）** |

**(I) は voice-006 から直接読める。(II) は voice-006 から読めない（gap-1 の奥にある）。** 以下の候補はこの区別とともに記録する。

## 1. Need Candidate 一覧（生成過程の記録）

> 各候補について「人間がなぜそう考えたか／根拠／確実性／推測部分」を記録する。確実性は「その候補が妥当である度」ではなく「**voice-006 からその根拠がどれだけ直接読めるか**」を指す。

### Candidate A — 資金支援の不足（種類 I: 仲介者の資源 Need）
- **人間がそう考えた理由:** 公開ページが寄付を募り、運営資金の約7割が民間寄付と明示している。
- **根拠:** JAR 公開支援要請（寄付募集の明示）。
- **確実性:** 高（公開要請に直接書かれている＝JAR 自身の声）。
- **推測部分:** 「不足額・緊急度の規模」は不明。資金を募っていることは事実だが、それが今の最大ボトルネックかは voice-006 から読めない。

### Candidate B — ボランティア（人手）の不足（種類 I: 仲介者の資源 Need）
- **人間がそう考えた理由:** 公開でボランティア参加（One Action for Refugees 等）を募集している。
- **根拠:** JAR 公開支援要請（ボランティア募集の明示）。
- **確実性:** 高（公開要請に直接記載）。
- **推測部分:** 必要人数・どの活動の人手が足りないかは不明。

### Candidate C — 翻訳/言語支援の不足（種類 II: 当事者個人の Need を推測）
- **人間がそう考えた理由:** 活動分野に言語/コミュニティ支援が含まれ、tags に translation がある。
- **根拠:** JAR の活動分野（言語支援）＋ obs-006 の observed_bottleneck に translation。
- **確実性:** 中（活動分野としては明示。だが「不足している」は推測）。
- **推測部分:** **需要規模・現在の不足量・誰が必要としているか**。これは個人の Need の推測であり、voice-006 内に当事者がいない（種類 II）。

### Candidate D — 法的支援の不足（種類 II: 当事者個人の Need を推測）
- **人間がそう考えた理由:** 活動分野に「法的支援（難民申請等）」が掲げられている。
- **根拠:** JAR の活動分野（法的支援）。
- **確実性:** 中（活動分野は明示・不足量は不明）。
- **推測部分:** 現在の不足量・緊急度・個別事案の内容（すべて gap-1 の奥）。

### Candidate E — 就労支援の不足（種類 II: 当事者個人の Need を推測）
- **人間がそう考えた理由:** 活動分野に就労支援がある。
- **根拠:** JAR の活動分野（就労支援）＋ obs-006 の observed_bottleneck に employment。
- **確実性:** 低〜中（活動分野ではあるが、現在のボトルネックかは最も不明）。
- **推測部分:** **これが今のボトルネックかどうか自体が不明**。活動領域の存在を Need 不足と読むのは飛躍。

## 3. 不確実性一覧

1. **需要規模が全候補で不明**（何件・どの程度足りないか）。
2. **「活動分野がある」＝「そこが不足している」ではない**（C/D/E に共通する飛躍）。
3. **どれが今の最大ボトルネックか**を voice-006 は語らない（A/B が募集されている事実はあるが優先度は不明）。
4. **当事者個人の実際の Need は一切観測されていない**（gap-1 の奥）。
5. obs-006 のキーワード抽出は原文の語の存在を示すだけで、不足の量・質を示さない。

**不確実性の総数: 5**

## 5. Voice と Need の距離

```
voice-006（JAR 公開要請・組織レベル）
   │ 距離0: 種類 I の Need（資金・人手）はここに直接ある
   │
   ▼ gap-2（Mujin が橋渡し済み）
JAR（仲介者）
   │ 距離大: 種類 II の Need（個人の翻訳・法的・就労）はこの先
   │
   ▼ gap-1（未観測・Mujin の外）
難民個人（Need 主体・voice-006 に不在）
```

- **種類 I（資金・人手）は Voice と距離ゼロ** — voice-006 そのものが JAR の資源 Need の表明。
- **種類 II（個人の Need）は Voice から二層遠い** — gap-1 の奥で、voice-006 からは推測しか届かない。
- 人間が C/D/E を「Need Candidate」と呼ぶとき、実際には**JAR の活動分野を当事者の Need に読み替えている**。これは距離を畳んでいる。

## 6. Gateway Voice から Need を推測する危険

- voice-006 は「助けてくれ（当事者）」ではなく「支えるための資源が足りない（仲介者）」。**ここから個人の Need を定義すると、不在の当事者に代わって誰か（人間 or AI）が「あなたが必要なのは翻訳だ」と決める**ことになる。
- これは **問題定義権力**そのもの（Saiyan Scouter 論点6）。当事者がテーブルにいないまま、その人の Need が外部から著者化される。
- 安全な形: **種類 I（JAR の資源 Need）への協力候補**として扱い、種類 II（個人の Need）は「JAR を通じて当事者本人に確認すべき未確定事項」として保留する。Mujin/人間が個人の Need を確定しない。

## 7. Saiyan Scouter 問題との関係

- **再発の入口はここにある。** Saiyan Scouter v1 は「人物評価」で失敗した。X-3 の危険は一段奥の「**Need 評価**」——不在の個人の Need を声から定義する権力。
- v1 のパラドックス（最困窮者が最低評価される）は、Need 定義層では「**声を上げられない個人の Need ほど、仲介者の活動分野に塗り替えられる**」として再現しうる。
- 回避: 種類 I と II を分け、II を確定しない。本文書が候補を**列挙**しても**確定・選定・書き込みをしない**のは、この回避の実践。Hermes が `cannot_define_need` を帯びるのと同じ境界を、人間の作業にも適用する。
- **未確定の保持** = Saiyan Scouter Claim を「未解決のまま保存」したのと同じ思想。Need Candidate を急いで Need にしない。

## 9. 追加観察が必要な部分

1. **JAR 本人（組織）への確認** — 公開要請の背後で、今の最大ボトルネックは何か（推測でなく当事者組織の声）。
2. **当事者個人の声（種類 A の Voice）** — gap-1 を越えた声が現れるか。現れれば種類 II が推測でなくなる。
3. **複数の Gateway Voice の比較** — 仲介者 Voice の Need 表明に共通パターンがあるか（pat-001 の追加検証）。
4. **種類 I で一周できるか** — 個人 Need を確定せず、JAR の資源 Need（資金・人手）への協力だけで Reality Feedback まで到達できるか。これが最も安全な次の実験。
