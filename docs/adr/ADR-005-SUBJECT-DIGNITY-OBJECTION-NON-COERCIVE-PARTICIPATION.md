# ADR-005 — Subject Dignity, Objection, and Non-Coercive Participation

- **Status:** Accepted
- **Date:** 2026-06-12
- **Context source:** [`docs/MUJIN_MVP_SPEC_GAP_ANALYSIS.md`](../MUJIN_MVP_SPEC_GAP_ANALYSIS.md)（MI-1〜11, MC-1〜5, MR-1〜7, MA-1〜6, X-1〜6）, [`docs/MUJIN_MVP_SPEC.md`](../MUJIN_MVP_SPEC.md), `claim_saiyan_scouter.md`, `mujin_reflections_from_saiyan_scouter.md`
- **Related:** ADR-001（Canonical Reality Feedback）, ADR-002（Boundary）, ADR-003（Relief Case Promotion）, ADR-004（Contribution Model）

---

## Context

Gap Analysis は、MVP 仕様が**不変条件の骨格は健全だが、ソース（Saiyan Scouter Claim と Mujin Reflections）が要求する運用メカニズムと思想の根幹を欠く**ことを示した。とりわけ致命的と判定されたのは:

- **MI-1 / X-3** — 当事者が Mujin・NPO・支援者・AI に異議を出す**独立経路**が皆無。SPEC の全フローは Dan-Go 参加能力と技術アクセスを前提とする。
- **MI-2** — 代理登録における「同意できない状態」と**後日同意確認義務**の不在。
- **X-2 / MR-5 / MA-4** — SPEC・ADR 全体の安全論が `advisory: true` / `authority: none` に依拠するが、ソースは「**advisory only は技術的免責であり道義的責任を免除しない**」と明言。
- **MC-3 / X-5** — Reach Gap の**定義の非所有原則**の欠落。

これらは「**『なぜあなたに接触したのか』に答えられないシステムを人間に使わせてはならない**」というソースの一線に直結する。Mujin が ADR-001〜004 で接続境界・正典・昇格・貢献を定義しても、**当事者の尊厳・異議・非強制参加を保証する設計原則が無ければ、それらの境界は権力構造に転化しうる。**

ADR-005 は、この欠落を**設計原則（design principles）**として確定する。実装仕様の確定（スキーマ・UI）は行わず、MVP 実装が満たすべき不変の原則を凍結する。

---

## Decision

以下10の決定を Mujin の不変設計原則として確定する。これらは ADR-001〜004 および MVP 仕様のすべての章に優先する上位制約である。

### D-1. 当事者の独立した異議経路
当事者は、**Mujin・NPO・支援者・AI エージェントの行動に対して、Dan-Go 参加能力や技術アクセスなしに異議を出せる。**
- 異議経路は Dan-Go の Claim 提起権（Art.3）から**独立**して存在する。
- 技術アクセスを要しない形態（電話・対面・代筆・第三者経由）で行使可能でなければならない。
- 異議の提出自体が当事者の評価・支援適格性に**不利に作用してはならない**。

### D-2. 代理登録における同意延期状態
**代理登録（`created_from: npo_proxy` / `relief_case` 昇格を含む）では「同意延期状態（consent-deferred）」を正式に認める。**
- 当事者が同意可能な状態になった時点で、**同意確認を行う義務**が登録側に生じる。
- 同意延期状態のケースは公開せず、Contribution の受付対象としない。
- 同意延期は「仮の同意」ではない。確認されるまで同意は**存在しない**。

### D-3. 同意できない状態は同意ではない
**同意できない状態（重篤・言語障壁・認知的制約等）は同意ではない。**
- 同意の前提は「当事者が同意の意味を理解できる状態にあること」である。この前提が成立しない状況での登録は、D-2 の同意延期状態としてのみ許される。
- 沈黙・無反応・不在を同意とみなさない。

### D-4. advisory_only は道義的責任を免除しない
**`advisory_only` / `authority: none` / `moves_money: false` は技術的免責であり、道義的責任を免除しない。**
- 「接続 → 支援 → 失敗」の連鎖で生じた害悪に対し、設計者・運営者・参加者の道義的責任は残る。
- advisory 不変条件は安全の**必要条件**であって**十分条件ではない**。Mujin はこれを安全の証明として用いてはならない。

### D-5. 非登録・撤回・拒絶は失敗ではない
**Mujin に登録されないこと、撤回すること、支援を拒むことは失敗ではない。**
- これらの選択は記録上「拒否」「失敗」として残らない（GR1）。
- 撤回理由の提出は任意であり、撤回が評価低下に繋がってはならない。

### D-6. Reach Gap 定義の非所有
**Reach Gap の定義は、設計者・支援者・AI・NPO・Dan-Go の誰か一人が所有しない。**
- 「この人は Reach Gap にいる」という判断を、誰も単独では下せない。
- Reach Gap の定義そのものを Dan-Go の公開交渉の対象とする。
- Mujin は Reach Gap を「解決した」と主張しない。

### D-7. 説明できない接触の不正当化
**「なぜあなたに接触したのか」を説明できないアウトリーチは正当化しない。**
- 接触の根拠を当事者に開示できないシステムを、人間の活動者に使わせない。
- MVP は能動的アウトリーチを持たない（自動発見・自動スカウト・自動アウトリーチ非実装）ため、接触は当事者起点（`direct_application`）または同意確認を伴う昇格（`relief_case`）に限る。

### D-8. Mujin 外部の共助の対等性
**Mujin 外部の共助 —— 家族・友人・地域コミュニティによる非公式支援 —— を、Mujin より劣ったものとして扱わない。**
- Mujin への登録が「正式な支援」の条件にならないことを保証する。
- 非公式の相互扶助を「可視化されていない価値ある共助」として設計上明示的に尊重する。

### D-9. 成功指標の当事者設定権
**成功指標は当事者が設定できる。Mujin が定義する「経済的独立」は、当事者が別の成功指標を望む場合に自動的に後退する。**
- 「経済的独立」が不適切なゴールである当事者（障害・慢性疾患・高齢・介護状況・制度的排除）への支援設計を Mujin は持つ。
- Mujin は当事者の定義する「成功」を、Mujin の定義する「成功」より優先する。

### D-10. 失敗・中断の非帰属
**失敗した支援や中断されたケースを、当事者の能力・属性・努力不足に帰属させてはならない。**
- Case の「失敗」「中断」は、Mujin の設計・支援者の行動・社会的条件・Mujin 自身の限界の問題として記録する（GR3）。
- 失敗は当事者のラベリングに使用しない。

---

## Consequences

### 正
- 当事者が支援提供側（Mujin / NPO / 支援者 / AI）に対して構造的に従属しない設計基盤が確立する。
- 「advisory only」への過信（X-2）が是正され、道義的責任が設計判断の中に明示される。
- 代理登録（relief_case 昇格・npo_proxy）の同意安全性が原則として保証される。
- Reach Gap・成功指標・非公式共助について、Mujin が「正統性の独占者」になる構造が排除される。

### 負 / 要対応
- D-1（非技術的異議経路）は、純デジタル MVP では満たせない。**人手・運用経路（電話・対面・代筆）の設計が MVP 完成条件に加わる。**
- D-2 / D-3 は同意モデルの再設計を要求し、SPEC §4/§8 の現行同意モデルと Gap X-1 の統一を必須にする。
- D-9 は「経済的独立が不適切な対象層」への支援設計という、MVP スコープに無い設計責務を生む。
- D-4 により、Mujin は「advisory だから安全」と主張できなくなり、害悪の道義的レビュー手続きが必要になる。

---

## Non-decisions（本 ADR が決定しないこと）

- 異議経路の**具体的実装形態**（電話番号・窓口・代筆フロー）。原則のみ確定し、手段は実装フェーズの設計とする。
- 同意延期状態・同意確認の**データスキーマ**（フィールド定義）。X-1 の同意モデル統一は別途行う。
- 「同意可能な状態になった」ことを**誰がどう判定するか**（D-2/D-3 の運用主体）。→ Open Question。
- Reach Gap の**定義そのもの**。本 ADR は「誰も所有しない」とのみ決め、定義は Dan-Go 公開交渉に委ねる。
- 成功指標の**具体的語彙**や `independence_roadmap` の Milestone 構造。
- アウトリーチの**実装可否**。Saiyan Scouter は未解決 Claim のまま保持する。
- 道義的責任の**帰属先・救済手続き**の詳細。D-4 は責任の存在を確定するが、責任分界の設計は別交渉とする。

## Implementation implications（実装が満たすべき含意・コードではない）

> 以下は将来の実装が満たすべき制約であり、本 ADR で実装は行わない。

1. **非技術的異議経路（D-1）** — Mujin MVP の完成条件に「Dan-Go・技術アクセスを要しない異議申し立て経路が少なくとも1つ存在する」を加える。
2. **同意延期状態（D-2/D-3）** — Mujin Case の同意モデルに `consent-deferred` 状態と「同意確認義務」を表現できること。確認まで非公開・Contribution 非受付。
3. **道義的レビュー（D-4）** — 害悪が観測された Case について、advisory 不変条件の充足とは独立に、道義的責任のレビュー記録を残せること。
4. **非帰属記録（D-10）/ 拒否非記録（D-5）** — Case 閉鎖・撤回・非登録において、原因を個人属性に帰属する記述を構造的に許さない記録形式。
5. **成功指標の当事者設定（D-9）** — 当事者設定の成功指標が Mujin 既定指標に優先する表現。
6. **発見経緯の開示（D-7）** — `created_from` に対応する「なぜ接触されたか」を当事者が照会できる経路。
7. **非公式共助の尊重（D-8）** — `/transparency` 等で「Mujin 登録は正式支援の条件でない」「Mujin 外の共助も対等」を明示。

これらは Gap Analysis の MI-1〜11 / MC-1〜5 と一対一で対応する。

## Relationship to ADR-001〜004

| ADR | 関係 | 整合の要点 |
|---|---|---|
| **ADR-001**（Canonical Reality Feedback） | **強化。** D-4 により、Reality Feedback の `requires_human_review: true` は「advisory だから安全」の根拠ではなく**道義的責任を伴うレビュー**と再解釈される。append-only・正典指定は不変。 | 矛盾なし。D-4 が ADR-001 の human review の意味を深める。 |
| **ADR-002**（Boundary） | **補完。** ADR-002 は Dan-Go↔Mujin の READ/WRITE 疎結合を定めるが、D-1 は**その境界の外**に、当事者→Mujin/NPO/支援者の独立異議経路を追加する。これは Dan-Go 経由ではない第三の経路であり、ADR-002 の「Mujin は Dan-Go を読み Reality Feedback を返す」構造と並立する。 | 矛盾なし。D-1 はデータ境界ではなく当事者権利の経路で、ADR-002 の疎結合を破らない。 |
| **ADR-003**（Relief Case Promotion） | **強化。** D-2/D-3 は昇格ゲートの `consent_obtained` を**「同意できない状態」への対応込みで厳格化**する。relief_case 昇格は同意延期状態を経て、同意確認後に promoted となる。D-5 は「昇格されない Relief Case」も失敗ではないことを保証。 | 矛盾なし。ADR-003 の verified→consent_obtained→promoted を D-2/D-3 が精緻化。 |
| **ADR-004**（Contribution Model） | **補完。** D-9 は Contribution の成功指標を当事者設定権の下に置く。D-10 は失敗 Case を貢献者・当事者のスコアに転嫁しない（ADR-004 の「スコア・債務を持ち込まない」と一致）。D-8 は Mujin 外の共助を Contribution の優劣に組み込まない。 | 矛盾なし。ADR-004 のスコア・債務排除を D-9/D-10 が当事者側から補強。 |

**横断的整合:** ADR-005 は ADR-001〜004 の上位に立つ**当事者尊厳の制約層**であり、いずれの ADR とも対立しない。むしろ各 ADR が定義した境界・正典・昇格・貢献が**権力構造に転化するのを防ぐガード**として機能する。
