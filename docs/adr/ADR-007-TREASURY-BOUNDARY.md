# ADR-007 — Treasury Boundary

- **Status:** Proposed（境界設計。Phase E の実装前提。当事者参加経路の保証つき Dan-Go 交渉に服する）
- **Date:** 2026-06-13
- **Context source:** Mujin Constitution 第7章（第25・26・27条）・第14条・第17条, Master Plan §13（Treasury Layer）・§8.3（MacBook Program）・MQ-16/MQ-19, Discovery Report C-3（`moves_money: false` と資金の緊張）, ADR-008 D8-7（金銭的補償の未決）, Cross Review §5（コストの先行）
- **Related:** ADR-002（境界——本 ADR はその資金版）, ADR-004（Contribution——funding 型）, ADR-005/006（尊厳・憲法）, ADR-008/011（補償・記録）, claim-mujin-governance-001（Dan-Go への役割依頼の先例）

> **moves_money ≠ governance. Funding is not control. Contribution is not ownership.**
> **Sponsorship is not case selection power.**

---

## Context

Mujin は当事者の尊厳（ADR-005）・憲法（ADR-006）・異議（ADR-010）・責任（ADR-008）・記憶（ADR-011)を**資金より先に**制度化した。この順序は意図的である: 資金は最も速く権力に転化する資源であり、受け皿の制度がない状態で流れ始めた資金は、必ず統治権・ケース選定権・当事者への影響力の形をとって沈殿する。

未確定のまま残っている境界が三つある:

1. **Dan-Go との境界**: Dan-Go の全レイヤは `moves_money: false` を不変条件とする。一方 Mujin は資金・物資を現実に動かす。Discovery Report C-3 はこの緊張を最初に指摘し、MVP v1.1 D-7 系の整理（「Dan-Go レイヤ上は advisory 記録に留める」）は方向を示したが、**会計責任の所在**は未確定。
2. **資金と権力の境界**: 憲法第25条（資金は支援であって投資ではない）は原則を宣言したが、資金源別の運用規律（寄付/協賛/助成金/DAO/GitSea/ClawBank/財団）は Master Plan §13 の表に留まり、決定になっていない。
3. **責任制度との境界**: ADR-008 D8-7 は金銭的補償を「ADR-007 確定後の追補」として保留した。Cross Review §5 は「制度コストが Treasury 統治より先に走る」順序のジレンマを指摘した。

本 ADR はこれらの境界を確定する。**Treasury の実装は Phase E 以降であり、本 ADR は境界の凍結のみを行う。**

---

## 検討 — Mujin Treasury とは何か

Mujin Treasury とは、**Mujin の活動に流入・流出するすべての価値（資金・物資・機器・サービス提供枠）の受領・保管・支出・公示を行う現実世界の機能**である。

Treasury は何でないか:
- **投資ファンドではない**（リターンを生まない・約束しない）。
- **配分委員会ではない**（「誰を支援するか」を決めない——それは同意・human review・needs の領分）。
- **Dan-Go の一部ではない**（Dan-Go は資金を動かさない。観察するだけである）。
- **統治機関ではない**（金は発言力に変換されない）。

---

## Decision

### D7-1. Dan-Go は資金を動かさない。Mujin Treasury は Dan-Go の外側にある

- Dan-Go の全レコード・全レイヤの `moves_money: false` は**永続的に維持**される。Dan-Go は資金移動を**観察・記録の対象**とするが、執行・保管・指図のいずれも行わない。
- Mujin Treasury は **Dan-Go の外側の現実世界の機能**であり、その法的・会計的・道義的責任は Mujin の運営主体（法人格は D7-12/MQ-19）が負う。
- **Treasury の記録は Dan-Go に advisory feedback として返せる**（ADR-001 の正典経由、append-only）。**ただし Dan-Go はそれにより会計責任を負わない**——feedback は観察報告であり、監査証憑でも承認でもない。Dan-Go 側に「Mujin の会計を承認した」という状態は構造的に発生しない。
- この境界は ADR-002（データの疎結合）の資金版である: **価値は境界を越えない。観察だけが越える。**

### D7-2. 資金提供者は統治権を持たない（funding is not control）

資金・物資・サービスの提供は、その量・継続性・形態にかかわらず、以下の**いずれにも変換されない**:

- Mujin のガバナンス上の発言力・議決相当の影響力（憲法第25条）。
- **ケース・当事者の選定権・指名権**（D7-5）。
- ケース情報・当事者情報への閲覧権（第17条・Master Plan §13.3）。
- Steward・監査人・Panel 等の人事への関与（ADR-010 D10-2 の独立性を資金側から侵食しない）。
- 優先的な透明性（大口提供者向けの特別報告＝当事者への接近は存在しない）。

**金で買えるのは、条件が閉じたという公開の事実だけである。**

### D7-3. 資金源の区別と受け入れ規律

| 資金源 | 性格 | 受け入れ規律 | 拒否条件（受けない金） |
|---|---|---|---|
| **寄付（個人）** | 基礎資金 | 使途指定は「領域」まで（教育・住居等）。個別ケース指名は本人合意経路（D7-5）を経る | 当事者情報・物語・接触の要求を伴う寄付 |
| **企業協賛** | 物資・技術・資金 | ブランド表示は事実の範囲（「機材提供: X社」）。契約は公開 | 採用パイプライン化・当事者へのマーケティング・独占条項 |
| **助成金** | 大型・報告義務つき | 報告は構造指標と資金フローで行う | 当事者の定量的「成果」報告（卒業率・就労率・自立率）を要件とする助成——**受けない**（§9 の成功再定義と非両立） |
| **DAO / 暗号資産** | 越境・小口・検閲耐性 | on-chain 透明性は第14条と親和。法的整理（D7-12）後に受け入れ | ガバナンストークン等による決定権の購入。投機的な値上がり益の受け皿化 |
| **GitSea 系** | OSS 貢献経済からの還流 | 「観察による透明化」原則と整合する範囲で受領 | reward 概念の再導入を伴う設計（refused concept は refused のまま——MAPPING_TABLE 継承） |
| **ClawBank 系** | コミュニティ相互扶助金融 | 当事者コミュニティ自身が管理する小規模プールとして実験。Mujin 本体は保管を**代行しない** | Mujin による支配・信用スコア化 |
| **財団（Mujin 基金）** | 長期安定 | 保守的運用・基金自体の公開監査 | 基金規模の自己目的化（規模は成功指標ではない） |

**共通規律**: 出所が確認できない資金・条件が非公開の資金・本 ADR の拒否条件に触れる資金は、額にかかわらず受領しない。**受けない金の記録も透明性の一部**として公示する（何を断ったかは、何を受けたかと同じだけ制度を語る）。

### D7-4. Treasury と Contribution の関係

- 資金・物資の提供は、既存 Contribution モデル（ADR-004）の `funding` / `supplies`（将来拡張）型の**記録**として表現される。**Treasury は新しい貢献概念を作らない**——Treasury は Contribution の「現実世界での執行・保管」面を担う機能であり、記録体系は単一のまま。
- Contribution の不変条件（スコア無し・債務無し・earning-back 無し・**contribution is not ownership**）は資金にも全面適用される。大口の funding 貢献も、1時間の翻訳貢献も、記録上対等の「条件を閉じる貢献」である。
- 貢献の `status`（offered → committed → delivered → verified）は資金にも適用され、`delivered` の検証は Treasury の公示と突合できる。

### D7-5. ケース選定権の遮断（sponsorship is not case selection power）

- 資金提供者が「この人を支援したい」と望む場合、その意思は**本人合意の経路**を経る: ①提供者は領域・条件への貢献として申し出る → ②当該ケースの当事者に（身元を明かさず）打診される → ③当事者が受諾した場合のみ接続される。**当事者には拒否の完全な自由があり、拒否は記録上不利にならない**（withdrawal is not failure の資金版）。
- 「支援対象の選定」を実質的に行う指定寄付スキーム（特定属性・特定地域への限定を装った個人指名）は受領しない。
- 物資（MacBook 等）の指定提供も同一規律に服する。

### D7-6. MacBook Program の資金・物資管理

- MacBook Program は**教育・独立支援の道具であり、支援の条件ではない**（憲法第27条・Master Plan §8.3）。機器の受領は他のいかなる支援の前提にも評価にもならない。
- **贈与会計**: 機器は贈与として記録され、貸与資産台帳（返却管理・使用監視）を**作らない**。Treasury が保持するのは「いつ・何台・どの経路で贈与されたか」の流れの記録のみで、**受領者と機器を紐づける継続的な台帳を持たない**（追跡しない贈与——売却の自由を含む、§8.3 の設計の会計的裏付け）。
- 協賛機器（企業リファービッシュ等）も受領後は同一の贈与規律に入る。協賛企業は配布先の情報を受け取らない（D7-2）。
- 配布の非選別（先着・抽選・対象全員）の方法選択は Treasury の権限ではない（Treasury は配るものを保管するだけで、誰に配るかを決めない——D7-7 の一般原則の適用）。

### D7-7. Treasury は配分を決めない（needs が決め、Treasury は応える）

- 支出の起点は常に**ケースの needs / 教育プログラムの所要 / 制度運用費（ADR-010/008/011 の経路・Panel・記録）**であり、Treasury は「予算があるから使う」「目立つケースに出す」という起点を持たない。
- Phase 51 Resource Memory の原則を継承する: **「資源は配分ではない。保有は義務ではない。可用性は移転ではない」**——Treasury の残高の公示は、誰かへの支払いの約束ではない。

### D7-8. Treasury と Accountability の関係・金銭的補償

- Treasury の運用（受領・支出・拒否・遅延）は ADR-010 の**異議の対象**であり、ADR-008 の**道義的レビューの対象**である（資金の誤りも T 系トリガーになる——「会計上適正」は道義的免責ではない。advisory only is not moral immunity の会計版）。
- Steward・監査人・Panel の予算は**運営予算と分離して公示**される（ADR-010 D10-2 の独立予算要件を Treasury 側から保証する——**責任制度の財布を運営が握らない**）。
- **金銭的補償**（ADR-008 D8-7 で保留）: 本 ADR は補償の**資金的受け皿**（補償引当の区分経理・公示方法）を定めるが、**補償制度そのものは ADR-007 単独では確定しない**——補償の要件・水準・手続きは ADR-008/011 への追補として、当事者参加の交渉で別途定める。それまでの経済的害悪への応答は、既存の直接支援（D7-9）の優先適用による。
- Accountability Memory（ADR-011）には Treasury 関連事案も同一規律（主体軸集計の禁止・構造優先の帰属）で記録される。

### D7-9. 当事者への直接資金 — 監視しない贈与

- 生活緊急資金等の当事者への直接給付は**贈与**であり: 使途を監視しない・報告を求めない・「正しい使い方」の物語を要求しない・受給が他の支援の評価に影響しない（Master Plan §13.4 の決定化）。
- 直接給付の記録は金額帯と領域の集計のみ公示し、受給者を特定・推定できる粒度では公開しない（D7-10）。

### D7-10. 透明性レポート — 公開と保護の非対称

- **公開する**: 全収入（源泉区分別）・全支出（領域別）・拒否した資金（D7-3）・残高・補償引当・責任制度予算の分離状況・資金フローの時系列。形式は append-only・定期公示・公開監査可能（第14条）。
- **公開しない**: 当事者を特定・推定しうる一切（個別給付の対象・ケース別支出の細目・小標本の交差集計——ADR-011 D11-7 の小標本抑制を会計にも適用）。
- 原則は Master Plan §10.2 の非対称: **金の流れには最大の透明、金が届いた人には最大の保護。** 「説明責任」を理由とする当事者情報の開示要求（助成元・メディア・行政）には D7-3 の拒否条件と憲法第25条で応じる。

### D7-11. 資金不足時の優先順位

資金が不足したとき、何を守り何を縮めるかを、危機の最中ではなく**今**決めておく:

1. **第一順位（最後まで守る）**: 進行中ケースの当事者の安全に直結する支出・**異議経路の運用費（ADR-010 の音声系を含む三系統）**・撤退時の当事者保護（憲法第24条）。
2. **第二順位**: 責任制度（Panel・記録・追跡監査）の継続。
3. **第三順位**: 新規ケースの受け入れに伴う支出・教育プログラムの新規開始。
4. **最初に縮める**: 運営の利便・広報・本 ADR 群の拡張的整備。

- **新規受け入れの停止は、進行中の支援の切り捨てに常に優先する**（縮むときは入口から縮み、出口からは縮まない）。
- 優先順位の発動・変更は公示され、異議の対象になる。Cross Review §5 が指摘した「制度コストの先行」に対し、本順位は**異議経路を運営利便より上位に固定する**ことで応答する——金が尽きるとき最初に消えるのが当事者の声であってはならない。

### D7-12. 実装前の未解決事項（法人格・法務・会計・税務）

以下は本 ADR では確定せず、**Phase E 実装前に解決を要する前提条件**として登録する:

| 項目 | 内容 |
|---|---|
| 法人格（MQ-19） | 財団・協同組合・非営利法人・複数法域分散のいずれか。第25条（資金は権利を買わない）・第29条（当事者参加）と整合する形態の選定 |
| 会計基準 | 贈与会計（D7-6/D7-9 の「台帳を持たない贈与」）と制度会計の整合。監査人（会計）の選任 |
| 税務 | 寄付控除の可否・国外送金・暗号資産の受領と換金の税務整理 |
| DAO/暗号資産の法的整理 | 受領・保管・換金の法域別適法性（D7-3 の受け入れ前提） |
| 雇用・報酬 | Steward・監査人・翻訳者への報酬支払いの法形式（独立性と雇用関係の緊張） |
| 越境送金 | Global Refugee Program（Master Plan §14）における対制裁・対 AML 整理——**難民支援送金は最も誤解されやすい資金フロー**であり、法務なしに開始しない |

**Treasury は Phase E 以降の実装対象であり、Phase C では実装しない。** Phase C〜D の制度運用費は、Treasury 統治の確立前の暫定経理（本 ADR の D7-2/D7-10/D7-11 を先行適用した最小限の公示つき）で賄い、Phase E で正規 Treasury に引き継ぐ。

## Consequences

### 正
- Discovery Report C-3 以来未決だった `moves_money: false` と実資金の境界が確定する（Dan-Go は観察のみ・会計責任ゼロ）。
- 資金→権力の全変換経路（統治・選定・閲覧・人事・優先透明性）が明示的に遮断される。
- ADR-008 の補償保留・ADR-010 の独立予算・Cross Review の優先順位問題が、それぞれ受け皿（D7-8/D7-11）を得る。
- 「受けない金の公示」により、資金規律が事後検証可能になる。

### 負 / 要対応
- D7-3 の拒否条件（特に成果報告型助成金の拒否）は、**受けられる資金の総量を構造的に減らす**。誠実さの値段であり、意図的に支払う。
- 「台帳を持たない贈与」（D7-6/D7-9）は、一部の法域・助成元の会計慣行と衝突しうる（D7-12 で解決必須）。
- 暫定経理（Phase C〜D）は正規 Treasury より統制が弱い期間を作る——Cross Review の指摘どおり、最も制度が薄い時期に最初の支出が走る。

## Non-decisions
- 金銭的補償の要件・水準・手続き（ADR-008/011 への追補・当事者参加交渉で確定）。
- 法人格・法域の選定（D7-12 の前提条件群）。
- 暫定経理の細目（Phase C 運用開始時に最小構成で定め公示する）。
- ClawBank 系プールの設計（当事者コミュニティ主導の実験として別途）。

- **ADR-004**: Treasury は Contribution の執行面であり記録体系を二重化しない（D7-4）。スコア・債務・ownership の排除を資金に全面適用。整合。
- **ADR-005/006**: 第25〜27条の運用化。非対称透明性（D7-10）は憲法第14条＋当事者保護の両立。整合。

- **ADR-010**: 独立予算の Treasury 側保証（D7-8）・資金不足時の異議経路最優先（D7-11）。整合。
