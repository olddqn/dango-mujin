# ADR-011 — Accountability Memory

- **Status:** Proposed（制度設計。ADR-008 と一体で当事者参加経路の保証つき Dan-Go 交渉に服する）
- **Date:** 2026-06-13
- **Context source:** ADR-008 D8-9（Accountability Memory の骨子）・D8-10（権力化への歯止め）, Mujin Constitution 第4条（人間価値の非計測）・第13条（append-only）・第15条（道義的免責の否定）, Relief Case Memory の系譜（"Care memory is not control."）
- **Related:** ADR-008（記録される手続きの本体）, ADR-010（入口）, ADR-006（不可侵条項）, ADR-001（append-only の正典思想）

> **記録 ≠ 評価。記録 ≠ スコア。記録 ≠ 信用。記録 ≠ 序列。**
> **責任は記録できる。人間価値は記録できない。**

---

## Context

ADR-008 は道義的レビューの手続きを設計し、D8-9 で「すべてのレビューは append-only の Accountability Memory に記録される」と宣言した。しかし**責任の記憶**は、Dan-Go/Mujin 系のどの記憶レイヤとも異なる固有の危険を持つ:

- 貢献の記憶（Contribution Memory）は称えられる側の記録であり、ケアの記憶（Relief Case Memory）は守られる側の記録である。**責任の記憶は、問われた側の記録である**——それは最も容易にブラックリスト・信用格付け・追放名簿に転化する。
- 一方で、記録しなければ第15条は空文化する: 「直視の制度」（D8-1）は、直視した内容が消えるなら直視ではない。約束された構造修正の追跡（D8-9）は記録なしに成立しない。
- この緊張——**消えない記録と、烙印にならない記録の両立**——を設計するのが本 ADR である。

### 既存の記憶レイヤとの違い（必須検討事項）

| | Recognition Ledger（Phase 15） | Contribution Memory（GitSea/credit 系） | Relief Case Memory（Phase 18） | **Accountability Memory（本 ADR）** |
|---|---|---|---|---|
| 何の記憶か | 認知・承認の来歴 | 貢献の来歴 | ケアの観察の来歴 | **責任手続きの来歴** |
| 誰の記憶か | 認められる側 | 貢献する側 | 支援が届いた側（最大限保護） | **問われた側（権力側）＋構造** |
| 主たる危険 | 承認の序列化 | スコア化・債務化 | 監視化・vulnerability の定量化 | **烙印化・ブラックリスト化** |
| 既存の防壁 | "Recognition is not ranking" 系 | earning-back / debt の拒否（ADR-004） | "Care memory is not control." | **本 ADR が新設する** |
| 参照の向き | 本人が示すために使う | 本人が示すために使う | コミュニティの care 史の legibility | **構造の修正と約束の追跡のために使う。人物照会には使わない** |

共通の祖形は「記録は支配ではない」（append-only・advisory・contestable・reopenable）。Accountability Memory はこの祖形を継承するが、**記録される者が権力側である**という一点で方向が反転する: 他の3レイヤが「弱い側の記録を権力から守る」のに対し、本レイヤは「権力側の記録を、別の権力（吊るし・追放・格付け）の道具にしない」ことが課題になる。

---

## なぜ記録するのか

1. **約束の追跡** — 構造修正の約束は、期限つきで追跡されなければ謝罪の演出に堕ちる（D8-9・ADR-008 自己レビュー①-4）。
2. **構造の学習** — 同型の害悪の反復を、個人の記憶や在任者の善意に頼らず検出するため。
3. **第15条の実体化** — 道義的責任が「存在する」ことの制度的証拠は、責任が問われた履歴が消えないことである。
4. **届かなかった人の推定材料** — レビュー記録の分布は、異議経路に届かなかった害悪の存在を推定する唯一の手がかりになりうる（D8-10-5）。
5. **記録しない選択肢の検討と棄却**: 記録しなければ烙印は生まれない。しかしそれは「権力側の失敗だけが忘れられる」非対称を作る——当事者のケースは記憶され、運営の失敗は消える世界は、第5条の精神の逆転である。よって記録する。

---

## Decision

### D11-1. 性格の確定 — Accountability Memory は何でないか

Accountability Memory は**評価システムではない。スコアリングシステムではない。ランキングシステムではない。ブラックリストではない。信用格付けではない。** 具体的に、以下を構造的に禁止する:

- 主体別の事案数・「違反率」等の**集計値の算出と表示**（個人・NPO・企業・運営・Agent 運用者のいずれについても）。集計は事由別・帰属層別・構造指標としてのみ行い、**主体を軸にした集計は作らない**。
- 記録の**照会 API・検索機能を「人物・団体名による引き当て」の形で提供しない**（構造・事由からは引ける。人からは引けない——参照の向きの設計）。
- 記録に基づく**自動的な資格剥奪・関与排除・優先度低下**（ADR-008 D8-9: 自動排除はスコアリングの変種であり第4条違反）。
- 外部（行政・他団体・メディア・資金提供者）への**名簿・格付けとしての提供**。

### D11-2. 何を記録するのか

事案ごとに、手続きの**全段階**を append-only で記録する:

| 段階 | 記録内容 |
|---|---|
| レビュー開始 | トリガー種別（T1–T7）・開始日・Panel 構成（特定可能、第20条） |
| 説明要求 | 誰に・何の説明を求めたか |
| 回答 | 回答の内容（または無回答の事実と経過期間） |
| 事実確定 | Panel が確定した事実（争いがある場合は争いの所在も） |
| 複合帰属 | 構造・組織・個人・Agent 運用の各層への帰属の記述（D8-4 の重層記述） |
| 応答・救済 | 実施された応答（謝罪・修正・停止・公開説明等）と本人の受領選択 |
| 再発防止 | 約束された構造修正・期限・追跡結果（**履行/不履行は必ず記録される**） |
| 終了 | 終了の形態（解決・対応不能の理由つき終了・上訴へ移行）。**「終了」は事案の消滅ではなく状態である** |
| 不服・上訴 | Panel 決定への異議・Dan-Go 上訴の経過 |

### D11-3. 何を記録しないのか

- **当事者（害を受けた側）の身元・状況の詳細** — 事案記述は当事者を再特定できない形で書く。当事者の記憶は当事者のもの（Relief Case Memory の原則の準用）。
- **関与者の人格・動機への評価的記述** — 「不誠実だった」「悪意があった」は記録しない。記録するのは行為・経過・帰属の事実記述のみ（評価は記録の読み手の領分であり、記録自体に焼き込まない）。
- **道義的「重さ」の数値・等級** — 重大性のスコア化は格付けの入口である。「不可侵条項への違反である」という種別の事実は記録するが、点数・レベルは存在しない。
- **レビュー外の風聞・告発の内容** — 受理されていないものは Memory に入らない（噂の公文書化を防ぐ）。
- **当事者の選択（謝罪の受領拒否・不参加・撤回）** — これらが「非協力的」等の含意を持って記録されることを禁止する。記録されるのは選択の事実のみ、解釈なしで。

### D11-4. 誰について記録するのか

| 主体 | 記録の扱い |
|---|---|
| **構造（設計・規則）** | **最も詳細に記録**——構造は晒されても傷つかない（D8-8）。構造帰属と修正履歴は Memory の中心 |
| **組織（運営・NPO・企業）** | 組織名は限定公開層で記録。公開層では役割種別（「代理登録を行った NPO」等）に抽象化 |
| **個人（判断者・関与者）** | 限定公開層で特定可能（第20条の帰結——匿名の権力を作らない）。**公開層には個人名は出ない**（晒しの禁止、D8-8） |
| **Agent（運用者）** | Agent 名・バージョン・出力の事実＋運用者（設計承認者・追認者）を記録（D8-5 の複合帰属）。**Agent の記録は Agent 改善の材料であり、「危険な AI」名簿ではない** |
| **当事者** | **記録対象にしない**（D11-3）。当事者はこの Memory の主語にならない——問われる側の記憶であって、訴えた側の記憶ではない（訴えた事実の記録は ADR-010 の異議記録に属し、本 Memory とは**リンクを一方向**にする: 事案→異議参照は可、異議→事案の逆引きで異議者が辿られる構造を作らない） |

### D11-5. 公開の三層（D8-8 の Memory への適用）

| 層 | 内容 |
|---|---|
| **公開** | 構造帰属の全文・構造修正の約束と履行状況・事由別/帰属層別の件数分布・手続きの所要期間統計。小標本抑制（n 未満は秘匿——ADR-010 自己レビュー⑤-2 の準用） |
| **限定公開** | 事案の全記録（Panel・監査人・Steward・本人が望む場合の当事者・上訴時の Dan-Go 交渉） |
| **非公開** | 当事者を推定しうる一切・報復リスク評価・本人が非公開を望む救済の内容 |

### D11-6. 保存期間・撤回要求・忘れられる権利

**保存**: 記録は削除されない（第13条・append-only）。ただし**「消えない」と「使われ続ける」は別の問題**として設計する:

- **参照の減衰（reference dormancy）**: 終了から一定期間が経過し、再発・不履行のない事案は「休眠」状態に移る。休眠記録は構造学習の集計には残るが、限定公開層の個別参照には**再活性の手続き**（監査人の承認＋理由の記録）を要する。これは削除なき「忘れられる権利」の形である——**歴史は消えないが、過去は現在の照会対象であり続けない**。
- **撤回要求の扱い**: 問われた側（個人・組織）は記録の削除を要求できないが、**訂正記録の追加**（事実誤認の指摘・その後の修正履行の追記）を常に要求できる。当事者（害を受けた側）は、自身を推定しうる記述の**秘匿強化をいつでも要求できる**（これは即時に履行される——当事者保護は手続きを要しない）。
- **説明責任と忘れられる権利の境界**: 構造と組織には忘れられる権利はない（公開層の構造記録は永続）。個人には参照の減衰がある。**当事者には最初から記録されない権利がある**（D11-4）。——忘れられる権利は権力勾配の下流ほど厚い。

### D11-7. 匿名化の規律

- 公開層の記述は、組み合わせによる再特定（小コミュニティでの「時期×役割×事由」の交差）を防ぐため、**抽象度の下限**を監査人がレビューしてから公開する。
- 匿名化は当事者保護のためのものであり、**権力側の責任回避のための匿名化は行わない**（限定公開層では特定可能性を維持する——非対称原則）。

### D11-8. 誤ったレビュー結果・未完了案件の扱い

- **誤りの訂正**: Panel の事実確定が後に誤りと判明した場合、訂正記録を追加し、**誤った確定も消さない**（消すと「Panel は誤らない」という神話を作る——制度の可謬性の記録自体が D8-10 の歯止めの一部である）。誤って帰属された者には、訂正の公開層での明示（帰属の撤回の可視化）を保証する。
- **未完了案件**: レビューが完了しないまま停滞している事案は、**停滞自体が公開統計に表示される**（「未完了 n 件・最長経過期間」）。未完了の放置は新たなトリガー（T1 系）になりうる。**未完了を闇に沈めないことが、握り潰しの最後の防壁である**（ADR-010 D10-5 の Memory 版）。

### D11-9. Reach Gap との関係

- 本 Memory に記録されるのは「届いた害悪」だけである（D8-10-5 の継承）。**記録の不在は害悪の不在を意味しない**——この一文を Memory の公開層の定常的な注記とする（統計の誤読——「事案が少ない＝健全」——への構造的反論を記録自体に埋め込む）。
- 事由・経路別の分布は、どの層の害悪が制度に届いていないかの推定材料として Dan-Go 交渉に開かれる。解釈は所有されない（第22条）。

### D11-10. 権力化しない保証 — Memory 自体への歯止め

1. **Memory は判定しない**: 記録は前例として参照されるが、過去の帰属が将来の帰属を自動決定しない（D8-9 継承——「判例化しない前例」）。
2. **Memory を人事に使わない**: 役割の選任・解任・Panel 構成の判断材料として「主体別の過去事案の引き当て」を行わない（再発防止に必要な範囲の除斥——当該当事者への関与停止等——は事案の応答として行われ、Memory の照会としては行われない）。
3. **Memory の運用者を Memory が監視する**: Recorder・監査人による Memory の改変・参照は、それ自体が append-only のメタ記録を残す（記憶の番人の記憶）。
4. **第4条の最終防壁**: 本 Memory のいかなるデータも、人間・組織の「価値・信頼性・危険性」の計測値の入力にならない。これは D6-7 の不可侵条項（人間価値の非計測）の Memory への適用であり、**本決定自体を縮小する改正は受理されない**。
5. **Memory の廃止条件**（第28条）: 本 Memory は ADR-008 の手続きと運命を共にする。手続きが Dan-Go 交渉で廃止・置換される場合、Memory は新制度に**読み取り専用の歴史**として引き継がれ、新たな追記を停止する。

## Consequences

### 正
- ADR-008 の「直視の制度」が持続的な記憶を持ち、構造修正の追跡（最重要費目）が制度化される。
- 「消えない記録」と「烙印にならない記録」が、参照の向き・参照の減衰・層別の忘れられる権利という3つの仕組みで両立可能になる。
- 既存3レイヤ（Recognition / Contribution / Relief）との役割分担が確定し、記憶レイヤ群の全体設計が閉じる。

### 負 / 要対応
- 参照の減衰・再活性手続き・メタ記録は運用の複雑性を上げる（自己レビュー③）。
- 「主体軸の集計を作らない」制約は、組織の反復的問題の検出を遅くする可能性がある——構造・事由軸の集計で代替できるという本 ADR の賭けは、運用で検証を要する。
- 公開層の抽象化レビュー（D11-7）は監査人の恒常業務を増やす。

## Non-decisions
- Memory の物理的保存形式（実装事項。Phase A の append-only 系統との整合のみ要件として記録）。
- 参照減衰の具体期間（運用開始時に当事者参加の下で設定）。
- 上訴で Dan-Go に移った事案の記録の所在（Dan-Go 側の記録体系との接続は ADR-002 境界の規範版として別途交渉）。
- 法的開示要求（召喚状等）への対応(法域確定 MQ-19 後)。

## Relationship to 既存 ADR
- **ADR-001**: append-only・訂正は追記・event_hash の思想を継承。整合。
- **ADR-004**: 「記録 ≠ スコア・債務」の系譜の第4の適用（contribution→relief→objection→accountability）。整合。
- **ADR-005/006**: 第4条（人間価値の非計測）を Memory に適用し不可侵条項に接続（D11-10-4）。D-10（非帰属）の記録版（D11-3: 評価的記述の禁止）。整合。
- **ADR-008**: D8-9 の全面詳細化。Memory は手続きの影であり、手続きなしに Memory だけが存在することはない（D11-10-5）。一体採択。
- **ADR-010**: 異議記録との一方向リンク（D11-4）・小標本抑制・未完了の可視化を共有。整合。

---

*本 ADR は制度設計であり、実装・コードを含まない。記録の不在は害悪の不在を意味しない——Reach Gap は未解決であり、本 ADR はその解決を主張しない。責任は記録できる。人間価値は記録できない。*
