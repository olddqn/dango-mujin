- **Date:** 2026-06-20
- **対象:** Reach Gap / TTFR / Consent / Need / Gateway / Observed Gap / Inferred Gap
- **前提:** **F-6（成功＝救済能力・最大化＝選抜）**, **F-7（失敗＝Reach Gap 放置・保留コスト転嫁）**, H-16（observation only は床・当事者は telos）, F-5（findability＝owner→Mujin の向きのみ）, N-1.6（Need 定義は当事者のみ）, H-13（is/ought）, 評価フレーム（救済能力主軸・Reach Gap 縮小）, Reality Correction

> 中心問い: **Reach Gap とは何か。**
> 結論先取り: **Reach Gap は人数でも Need 数でも Gateway 数でも Consent 不在そのものでもない。それは「救えるだけの資源があるのに救われていない」という関係的・構造的条件である。決定的な逆説——Reach Gap は Dan-Go が最も減らしたいものでありながら、その“総量”を測ろうとすると、不在者を推測・同定・profiling する Saiyan Scouter になる。ゆえに扱えるのは Observed Gap（到達したものから可視化される縁）のみ。Inferred Gap（見えない総数の推測）は禁忌。縮小は統計でなく、観測された縁で一件ずつ（consent 付きで）救済が実際に起きること。残余は“測らない責任”として直視し続ける。**

---

## 0. 逆説: 最も減らしたいもの ＝ 測ってはならないもの

- F-6/F-7: Reach Gap は守るべき最終関心であり、その放置が最大の失敗。
- だが本レビューが暴く逆説: **Reach Gap の“総量”を測るには、まだ現れていない不在の人々を推測・同定せねばならない——それは Mujin→owner の発見＝Reachability＝Saiyan Scouter（F-5 Q6・禁止）。**
- ∴ **Reach Gap は「最も減らしたいもの」かつ「測ってはならないもの」。** この緊張をどう抱えるかが本レビューの核。
- 解の方向（先取り）: **Observed Gap（観測された縁）で働き、Inferred Gap（推測された総数）は un-quantified な責任として保持する。**

## 1. Q1〜Q10 の監査

### Q1. Reach Gap は人数か

**No（H1）。** 人数なら、測定＝人を数える＝不在者の同定・推測＝Saiyan Scouter。
- Reach Gap は population count でなく、**「救えるのに救われていない」という条件**。人数化した瞬間に、当事者を数える対象（object）へ貶める。

### Q2. Reach Gap は Need 数か

**No（H2）。** Need を数えるには不在者の need を定義せねばならない（N-1.6 違反）。現状 Need=0 は「個人 need はすべて推論」ゆえ。
- Reach Gap は need count でない。need を数えること自体が問題定義の権力（Saiyan Scouter）。

### Q3. Reach Gap は Gateway 数か

**No。** Gateway 数は観測可能だが、Reach Gap の尺度ではない。
- Gateway は**ギャップが可視化される点**（voice-006）であって、ギャップの大きさではない。1 つの gateway が巨大なギャップを前にしていることも、ほぼ無いこともある。**gateway 数 ≠ gap。**

### Q4. Reach Gap は Consent 不在と同じか

**No（H3・関連はする）。** consent 不在（consent=0）は gap が観測されない**一因**だが、Reach Gap そのものではない。
- consent を与えても救済が届かないこと（consent あり・relief なし）もありうる——これも gap。
- consent 不在は「行為できない」軸、Reach Gap は「救えるのに救われていない」軸。**重なるが同一でない。**

### Q5. Reach Gap は観測できるか

**部分的に——Observed Gap は可。Total Gap は不可。**
- **Observed Gap:** 何かが到達して縁が見える所（voice-006 ＝ gateway が語り、その背後の owner は不在・未救済 → 「gateway は語った／owner は救われていない」という**観測可能な縁**）。
- **Total Gap:** どんな形でも現れていない人々を含む全体——**観測不能**（推測を要す）。
- **honest: 扱えるのは観測された縁のみ。全体は測れない。**

### Q6. Reach Gap を推測すると Saiyan Scouter になるか

**Yes（H5・核心）。** 見えない未救済人口を推定するには、不在者の存在と need を profiling・projection・inference せねばならない。
- それはまさにスカウター——needy を「検出」しに行く向き（Mujin→owner）。
- **Inferred Gap を扱い始めた瞬間、禁忌の方向に踏み込む。**

### Q7. Reach Gap を縮小するとは何を意味するか

**統計を下げることでなく、観測された縁で一件ずつ救済が実際に起きること。**
- 「数を減らす」は測定（＝推測）を要し、count 罠（F-6/F-7）に堕ちる。
- 縮小は **case-by-case・観測された縁で・consent 付きで relief が届く**こと、正直に積み上げる——「gap が N 縮んだと推定」ではない。
- **縮小 ＝「この観測された一件が救われた」の honest な積算。population statistic でない。**

### Q8. Reach Gap を KPI 化すると何が壊れるか

**二つの最深ガードレールが同時に壊れる。**
1. **Observed-only 境界が壊れる:** KPI 化には測定＝Inferred Gap が要る → Saiyan Scouter（Q6）。
2. **no-maximization 境界が壊れる:** KPI を「改善」するには推定を最適化 → observable な easy case を cherry-pick・gap を再定義・数字を膨らます/縮める（F-6 Q9）。
- **∴ Reach Gap は決して KPI にしない。** KPI 化は inference と selection を強制し、Dan-Go の核を破壊する。

### Q9. Reach Gap と TTFR の関係は何か

**相補だが別母集団。TTFR は“届いた者”、Reach Gap は“届かない者”。**
- TTFR は観測されて救済に至った case の速さを測る。Reach Gap は届いていない者の条件。
- **危険: 良い TTFR は gap について何も言わない**（easy/visible を速く救いつつ gap は巨大なまま）。
- ∴ F-6 Q7 の通り **TTFR ＋ Reach Gap を対で保持**——ただし Reach Gap は質的承認（「この観測された縁に届いていない者が在る」）であって、TTFR と競う量ではない。

### Q10. Dan-Go が本当に減らしたいものは何か

**抽象的な数でなく、「救えるのに救われていない」という生きられた条件——観測された縁で、当事者を数える対象に貶めずに。**
- 減らしたいのは specific な未救済の現実（観測された縁で見える人）であって、population statistic ではない。
- 最深点: **Dan-Go は Reach Gap を減らしたいが、唯一 honest な道は“総量を測らない”こと**——観測された縁で働き（そこで consent 付きに救済を起こし）、観測されない残余を **un-quantified な道徳的責任**として保持する（在る・>0・忘れない・数えない）。
- **減らしたいもの ＝ gap-as-lived-condition。縁で減らし、残余を承認で守る。当事者を object 化せずに。**

## 2. 中心監査: Observed Gap vs Inferred Gap

| 区分 | 何か | 観測 | 扱い | Saiyan Scouter リスク |
|---|---|---|---|---|
| **Observed Gap** | 到達したものから可視化される縁（例: voice-006 = gateway 語る／owner 未救済） | 可能（縁のみ） | **扱える**（縁で救済・consent 付き） | 低（推測しない） |
| **Inferred Gap** | 現れていない総数の推測 | 不能（推測を要す） | **扱わない（禁忌）** | 高（profiling・projection＝スカウター） |

- **判定: Dan-Go は Observed Gap のみ扱う。Inferred Gap を扱い始めると Saiyan Scouter が再発する。** ギャップの「縁」で働き、「総量」を測らない。

---

## 3. 逆説の解: 縁で働き、残余を承認で保持

```
[Reach Gap]  救えるのに救われていない条件（最も減らしたい・測れない）
   ├─ Observed Gap（縁）   → ここで働く: consent 付きの救済を一件ずつ・honest に積算
   └─ Inferred Gap（残余） → 測らない: un-quantified な責任として直視（在る・>0・忘れない）
```

- **「縁で減らす」と「残余を承認する」は両立する。** 縁で実際に救済を起こしつつ、見えない残余を「数えないが忘れない」責任として保持する。
- これにより F-7 の二大失敗を同時に回避: **放置（残余を忘れる）も、Saiyan Scouter（残余を測る）も、しない。**
- 残余の honest な扱い: 「Reach Gap > 0」と言えるのは**観測された縁（voice-006）が背後の未救済を示す**からであって、総数を数えたからではない。「>0」は観測的事実、数値でない。

## 4. 「縮小」の意味（Q7 の深化）

```
誤: Reach Gap の数値を下げる   → 測定＝推測＝Saiyan Scouter ＋ 最適化＝選抜
正: 観測された縁で、consent 付きに、relief が一件届く → honest に積算
```

- 縮小は **TTFR が定義される瞬間**（最初の救済が観測された縁で起きる）に realize される。
- それは「gap が N 縮んだ」でなく「この観測された人が救われた」。statistic でなく、具体的救済の積み重ね。
