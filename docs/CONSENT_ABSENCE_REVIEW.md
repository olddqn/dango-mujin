> 中心問い: **Consent が存在しない場合、Dan-Go は何をしてよいのか。**
> 結論先取り: **「Consent 不在 → Observation Only」は person 領域については妥当だが、Dan-Go 全体の結論としては不完全。person 領域は観察のみで封じつつ、(a) Gateway 自身（consenting actor）の供給側領域、(b) Findability（受動的到達可能性）は正当に可能。最大の罠は「observation only」を恒久的保留＝不作為のアリバイにし、保留のコストを救われない当事者に負わせること。Observation only は person 領域の“床”であって Dan-Go の“天井”ではない。**

## 0. 罠: 美しい自制が静寂主義（不作為）に化ける

- H-15 で確立: consent 不在は person 影響行為を禁止する。**正しい。**
- だが危険: 「だから何もしない（observation only）」を**恒久的保留として固定**すると、評価フレームが最も警戒する事態——**「保留のコストを誰が払っているか」＝救われない当事者が払い続ける**——に陥る。
- Dan-Go の目的は「救えるだけの資源があるのに救われていない人を減らす」こと。**consent 不在を理由に当事者を忘却・放置することは、目的そのものの裏切り。**
- ∴ 本レビューの核: **consent 不在は person 領域を封じる（不可侵）が、Dan-Go を麻痺させてはならない。** 封じる所と、なお正当に動ける所を、正確に切り分ける。

## 1. Q1〜Q10 の監査

### Q1. Consent 不在は存在不在と同じか

**No（決定的）。** 当事者は**存在する**（voice-006 の背後に救われていない実在の人々）。欠けているのは consent であって、存在ではない。
- consent 不在を存在不在と混同すると、**当事者を不可視化・忘却**する——これは Dan-Go が避けるべき失敗そのもの。
- **当事者は「目的としては在（present-as-reason）、同意者としては不在（absent-as-consenter）」。** 存在は消えない。

### Q2. Gateway Voice は何を観察可能にするか

**Gateway 自身の領域を観察可能にする。** gateway が存在すること、状況を語ったこと、背後に救われていない人々が居りうること、供給側の事実（ボトルネック・容量・Case D/E の調整余地）。
- これらは **gateway の領域**の観察であって、不在当事者の私的現実の抽出ではない。

### Q3. Gateway Voice は何を禁止し続けるか

**person 領域を封じ続ける（H-15 §2）。** 不在 owner の need 定義・代弁・solution 実行・接触・Contribution 帰属・Decision 代行・Cooperation 割当。
- Gateway Voice は person 領域の封印を**一切解かない**。

### Q4. Observation はどこまで許されるか

**gateway 領域・公開面・「voice-006 が存在する」事実まで。person への到達・推論は不可。**
- 許可: gateway の状況、供給側構造、F-1.5/F-1.7 の surface/object、voice の存在。
- **禁止: 観察を通じた当事者の need 推論・profiling（観察経由の Saiyan Scouter）。** observation は「提供された/公開された」ものを記録し、不在者の私的現実を抽出しない。

### Q5. Need Candidate は作れるか

**当事者の need についての candidate は No。Gateway 自身の self-stated need は条件付き Yes。**
- 不在 owner の need を candidate 化することは、**特定の need の推論**＝Saiyan Scouter（need 定義は当事者のみ・N-1.6）。candidate であっても不在者の need を主張すれば越境。
- ただし **gateway が自分の状況として述べた need（供給側ボトルネック等）**は、gateway consent のもと・gateway 領域と明示すれば candidate 化可。
- **境界: person-need candidate = 不可（現状 Need=0 が正しい）。gateway-self-need candidate = gateway consent ＋ person 領域と峻別の上で可。**

### Q6. Findability は許されるか

**Yes。** Findability は受動・人に到達しない（F-1.5/F-1.7）。Findability ≠ Reachability。
- 公開面・object の観察は当事者の consent に依存しない（誰にも到達しないから）。
- **むしろ積極的価値: Findability を保つことは、不在 owner が将来 Mujin を“見つけて自ら consent する”経路を開く。** consent 不在を解きうる唯一の正当な道（outreach でなく findability）。

### Q7. Participation は可能か

**当事者本人の participation は不可（不在ゆえ）。他の consenting actor の participation は可能。**
- 不在 owner は自ら動けない（participation は本人起点・F-4）。
- だが gateway・agent・発見し consent した他の human は participate できる。
- **境界: 不在 owner の代理参加は不可。consenting actor 自身の参加は可。**

### Q8. Human Approval は何も開けないのか

**person 領域は開けないが、gateway 領域・系内行為は開ける。**
- 二鍵原則（H-14 §3）: person 影響行為は Approval ∧ 当事者 consent。**owner consent 不在ゆえ person 領域の二鍵は揃わず開かない。**
- だが gateway 領域（gateway consent あり）・系内観察は Approval で開く。
- **Approval は無力ではない——正当に可能な仕事（gateway 領域）を統べる。ただし欠けた consent を代替はしない。**

### Q9. Consent 不在ケースは永続的保留か

**No（最重要の honest 修正）。** 二点:
1. **条件付き保留であって恒久的選択ではない。** person 領域の禁止は **consent が来るまで**続く standing prohibition。owner が現れ consent すれば解ける——永続と決めつけない。
2. **保留を不作為のアリバイにしてはならない。** 保留のコストは救われない当事者が払う（評価フレーム）。Dan-Go は**正当に可能なこと（gateway 領域の供給側調整・findability による到達可能性の確保）を能動的に追求**せねばならない。保留＝完了ではない。
- **∴ person 領域は consent 待ちで保留（正しい）、だが Dan-Go は「保留を達成」と勘違いせず、解禁経路（findability）と隣接可能領域（gateway）で動き続ける。**

### Q10. Consent 不在者は Dan-Go の外部なのか

**No（最深点）。** consent 不在・救われていない当事者こそ、Dan-Go が**存在する理由（telos）そのもの**。
- 「救えるのに救われていない人を減らす」——その人々が中心であって外部ではない。
- consent 不在は「**その人に行為してはならない**」を意味するが、「その人は居ない/関係ない」を意味しない。
- **彼らを「外部」と扱うことは、Dan-Go が回避するために作られた失敗（到達困難ゆえの忘却）そのもの。** 行為からは封じられても、目的としては内側の中心。

## 2. 中心監査: 「Consent 不在 → Observation Only」は妥当か

**部分的に妥当・重大な修正を要す。**

| 領域 | consent 状態 | 許される行為 | 「observation only」評価 |
|---|---|---|---|
| **Person 領域**（不在 owner） | consent 不在 | 観察のみ（存在の記録）。定義/代弁/実行/接触は禁止 | **妥当（床）** |
| **Gateway 領域**（gateway = actor） | gateway consent あり | 供給側調整・Case D/E（gateway 領域に限定） | observation only は**過小**（正当に動ける） |
| **Findability** | consent 非依存 | 公開面の観察・受動的到達可能性の確保 | observation only に収まるが**能動価値あり** |

- **判定: 「Consent 不在 → Observation Only」は person 領域については正しい“床”だが、Dan-Go 全体の“天井”として読むと不当。** gateway 領域の consented work と findability を不作為で放置すれば、保留のコストを当事者に転嫁する。
- **修正後の結論:** 「Consent 不在 → **（person 領域）Observation Only ＋（gateway 領域）consented 供給側調整 ＋（findability）受動的到達可能性の確保**、かつ保留にコストがあることの能動的自覚」。

## 3. 三領域の切り分け（H-16 確定）

```
consent 不在のもとで:

[Person 領域]    不在 owner       → Observation Only（定義/代弁/実行/接触 禁止）  ← 不可侵の床
[Gateway 領域]   gateway = actor  → gateway consent の範囲で供給側調整（Case D/E）
[Findability]    誰にも到達しない  → 公開面の維持で「owner が自ら見つけ consent する経路」を開く
        │
        ▼
  解禁条件: owner が現れ、自分自身について affirmative・specific・revocable に consent した時のみ
            person 領域が（二鍵: ＋Human Approval で）開く
```

- gateway 領域・findability は person 領域へ**漏れない**ことが条件（gateway consent の範囲超過で不在者に到達しない・findability は outreach に転じない）。

## 4. 保留のコスト（honest）

- person 領域の保留は**正しい**（consent 不可侵）。だが**コストはゼロではない**——救われていない当事者が、保留の間も救われないまま。
- 評価フレームの帰結: **「自制した」ことに安住しない。** 保留を選んだ以上、Dan-Go は (a) 解禁経路（findability）を能動的に保ち、(b) 隣接可能領域（gateway 供給側）で実質的に動き、(c) 「観察だけして満足」という静寂主義を自己監査し続ける義務を負う。
- **observation only が“達成”に見え始めたら、それは失敗の兆候。** 当事者はまだ救われていない。
