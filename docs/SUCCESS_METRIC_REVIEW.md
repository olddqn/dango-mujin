## 0. なぜ指標が Dan-Go の正体を決めるか

- 「何を測るか」は「何を目指すか」と同義。**成功指標を間違えると、組織は指標が報いる行動に最適化され、目的から逸れる。**
- 二つの指標族:
  - **Growth Metrics（量）:** discovery/participation/contribution/cooperation/consent の count。**最大化＝marketing/Saiyan Scouter を誘発。**
  - **Relief Metrics（救済能力）:** 救われていない人が救われているか。**TTFR を主軸とする。**
- Dan-Go の目的は「救えるのに救われていない人を減らす」。∴ **Relief Metrics のみが目的と整合し、Growth Metrics は目的を裏切る。**

## 1. Q1〜Q10 の監査

### Q1. Discovery Count は成功指標か

**No。** 到達・訪問の量であって救済でない（F-5 Q9）。高 discovery ＋ 救済ゼロ＝失敗。

### Q2. Participation Count は成功指標か

**No。** 活動量であって救済でない。多数の参加者がいても、救われていない当事者は救われていないまま。

### Q3. Contribution Count は成功指標か

**No。** 貢献数は活動量。しかも count 化は帰属→reputation→序列（H-11/H-13）を呼ぶ。救済とは独立。

### Q4. Cooperation Count は成功指標か

**No。** 協力の possibility が何件あっても救済とは別。count 化は actor 結合・割当（H-5 違反）を誘発。

### Q5. Consent Count は成功指標か

**No（重要）。** consent を「増やす KPI」にすると、**consent を製造する圧力＝強制・dark pattern** を生む（F-5 Q10 と一貫）。consent は質（自由・特定・撤回可能）であって数でない。

### Q6. Relief Count は成功指標か

**方向は正しいが、生の count 化は危険。** Relief（救済）は目的そのもの——だが「救済数を最大化」すると **easy case の cherry-pick**（救いやすい者を選び、救いにくい・不在の者を放置）を招く。これは目的「救われていない人を減らす」の**逆**。
- **∴ Relief は測るべき正しい対象だが、生の最大化 count にしない。** 誰が**まだ**救われていないか（Reach Gap）と対で見る。

### Q7. TTFR は成功指標か

**Yes——主軸。ただし限界の honest な明示が要る。**
- TTFR（Time To First Rescue）は「救いを必要とする者が、どれだけ速く最初の救済に至るか」を測り、救済能力に直結。TTFR-G（Gateway 救済）と TTFR-P（Person 救済）を区別。
- **限界: TTFR は“最初の救済までの速さ”であって“網羅”ではない。** 一部が速く救われても Reach Gap（決して届かない者）が巨大なら、良い TTFR は誤導しうる。
- **∴ TTFR を主軸とし、Reach Gap（なお救われない者・保留のコストの担い手）と併記して守る。**

### Q8. 量と救済能力はどう違うか

**量（is・記述的）は「どれだけ活動が起きたか」、救済能力（ought・目的）は「救えるのに救われていない人が救われているか」。** 直交する。
- 量が大でも救済能力ゼロはありうる（大量 discovery・救済ゼロ）。H-13 の is/ought と同型——**量から救済能力は導けない。** 目的は後者。

### Q9. 成功指標の最大化は Saiyan Scouter を再発させるか

**Yes——これが最深の警告。** **いかなる count でも「最大化」は選抜圧を生む。**
- 数を達成するには、**達成しやすい対象（見える・乗り気・救いやすい＝“戦闘力の高い”者）を選び、達成しにくい対象（不可視・不在・救いにくい者）を捨てる**。
- これは Saiyan Scouter そのもの——スカウターが高戦闘力を選ぶように、最大化 KPI が easy target を選ぶ。
- **Relief Count すら例外でない（Q6）。** ∴ **「指標を最大化する」という行為自体が、Dan-Go が存在する理由（救いにくい・不在の者）を裏切る構造を持つ。**

### Q10. Dan-Go が守るべき最終指標は何か

**「資源があるのに救われていない人（Reach Gap）の減少」を、TTFR を主軸に、selection を誘発しない形で。**
- 構成: **TTFR（速さ・主軸）＋ Reach Gap（網羅・なお救われない者の honest な可視化）。**
- 守り方: **最大化 KPI にしない。** 指標の役割は「スコアを上げる」でなく「**救われていない者から目を逸らさせない**」こと。指標が easy case を報い hard/absent case を捨てさせるなら、その指標は壊れている。
- **最終指標は“スコア”でなく“当事者”を守る:** 救われていない人を減らせているか、そして**減らせていないコストを誰が払っているか**を直視し続ける。

## 3. メタ危険: 「最大化」そのものが Saiyan Scouter（Q9 の深化）

```
[任意の count]
   │  「最大化せよ」という指令
   ▼
[選抜圧]  数を達成するため easy/visible/willing を選ぶ
   ▼
[Saiyan Scouter 再発]  hard/invisible/absent を捨てる ＝ Dan-Go の telos を裏切る
```

- **危険は「悪い指標を選ぶ」ことだけでなく、「良い指標でも最大化する」こと。** Relief すら最大化すれば選抜になる。
- **構造的保証: 指標を“最大化する KPI”として運用しない。** 指標は「救われていない者を可視化し、目を逸らさせない calibration」として運用する。score を上げる対象でなく、当事者を守る鏡。

## 5. 主要判定: 成功は「量」か「救済能力」か

**救済能力。** 量は成功でない（H-13 is/ought・量から救済は導けない）。
