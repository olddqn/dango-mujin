# Learning Is Not Prescription — Dan-Go Protocol Note

> **"Learning is not prescription."**
> **"Pattern is not prediction."**
> **"Recurrence is not ranking."**

## The Distinction

**Learning** — in the Dan-Go sense — is making care history legible
across phases. Phase 20 takes the care loop records from Phase 19,
the relief case records from Phase 18, and the aid route records from
Phase 17, and builds a pattern memory that links them. This cross-phase
linking allows a community to see, in one place, that a recurring type of
care need has been observed across multiple instances.

**Prescription** is telling someone what to do. A prescription implies
authority — the authority to define what the correct response is, to
require that response, and to judge non-compliance. Dan-Go has no such
authority. The `learning_is_prescription: false` and
`memory_prescribes_response: false` invariants are permanent on every
Phase 20 record.

## Why Learning Cannot Become Prescription

The care layer — from Phase 17 through Phase 20 — is built on voluntary
cooperation. Each phase has refused a coercive interpretation:

- Phase 17: "Need is not debt." The person in need is not obligated to
  receive help. The person offering help is not commanded to give it.
- Phase 18: "Relief is not proof." Recording a care outcome does not
  certify success or rank the response.
- Phase 19: "Care loop is not obligation." Reopening a care case does not
  compel new aid.
- Phase 20: "Learning is not prescription." Observing a pattern does not
  tell anyone what to do.

Each phase has the same refusal: observation is not command.

If pattern learning became prescription, the following would be true:
- A commons with a recurring food support pattern would be told to
  establish a regular meal program.
- A commons with an ongoing displacement relief pattern would be told to
  maintain permanent shelter capacity.
- Communities would lose the ability to decide their own scope of care.

Dan-Go avoids this by restricting itself to the record. The pattern
memory says: this has happened, and this is what it looked like across
Phases 17–19. The community decides what to do with that information.

## What the Pattern Memory Accomplishes (Without Prescribing)

1. **Cross-phase legibility.** A participant who wants to understand the
   care history of their commons can read the pattern memory and see the
   full chain from route suggestion through reopen through pattern
   observation. No prescription is required for this legibility to be useful.

2. **Voluntary coordination support.** Participants who want to coordinate
   recurring responses can use the pattern memory as a starting point.
   They design the coordination; Dan-Go did not.

3. **Contestability.** If a participant believes the pattern record is
   incorrect — that the observed count is wrong, that the pattern type
   does not capture the situation accurately, or that the linkage to
   specific care loops is mistaken — they can contest the record. The
   pattern memory is not authoritative. It is advisory and contestable.

## The Limit of Pattern Memory

The pattern memory log ends with `memory_certifies_resolution: false`.
When a community addresses a recurring need — by changing how they
coordinate food sharing, by establishing longer-term shelter support,
by resolving a tenancy dispute — the pattern memory does not certify
that the resolution is complete. It records that the community addressed
the situation. The situation may recur. If it does, a new recurrence
observation will be added. The memory grows with the situation.

Dan-Go does not decide when a pattern has been resolved. The community does.

## Protocol Phrase

> "Learning is not prescription."

This phrase appears in every Phase 20 runtime module. It is the commitment
that Dan-Go's cross-phase pattern memory will never be interpreted as an
instruction to any participant. The learning belongs to the community.
The prescription belongs to no one.
